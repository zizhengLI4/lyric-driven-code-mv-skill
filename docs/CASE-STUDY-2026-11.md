## 1. 取证方法与它的边界

| 环节 | 做法 | 产出 |

| 横向比对 | 6 帧拼 3×2 接触表，一次看完整条片子 | `dy_sheets/<id>.jpg`、`dy_sheets2/*.jpg` |
| 量化 | 时长、分辨率、作者归属、总时长 | `dy_summary.json` |

**边界（必须写清楚，避免把推断当事实）：**
- 只有画面证据，没有音频轨道分析，也没有原始工程。所有"切点对拍""BPM"判断一律未做 → 本文不给 BPM，也不宣称音画同步。
- 帧是"均匀采样"，不是逐帧。因此**能确认的是构图、HUD、字幕、装置与段落序**；**不能确认**的是单帧级动效曲线（缓动、粒子生命周期）。
- 分辨率、时长、发布时间是读取值；实现框架（Remotion / Canvas / AE）**未知**，任何"他是怎么渲染的"都是推断，本文标注为「推断」。

## 4. 拆出来的五条方法论（可直接指导写分镜）

**M1｜先选"系统"，再选"场景"。**
这位作者不是"歌词→画面"，而是"歌词→一个游戏/软件系统里的事件"。同一个"我"可以是玩家、可以是聊天的一方、可以是存档里的一帧。**选系统 = 选叙事视角**。
→ 分镜的第一层不是 `scenes`，而是 `device`（外壳），`scenes` 是外壳里切换的"界面页"。

**M2｜HUD 是这个作者的"抒情器官"。**
情绪不靠旁白，靠数值：好感度掉到 0、心情 -56、血量一路减、存档损坏、伪劣值 100%。**每个数字都对应一句歌词**（"结果却无法通关" ↔ 存档损坏）。
→ HUD 必须"可解释、可追溯、允许变坏"。

**M3｜标题牌 + 章节牌 + 关系卡 = 三段式骨架。**
开场标题牌（歌名/歌手/母题）→ 中段章节牌（第一章·他的冬天 / 2015-2018 / 初见-同游-月下-白首）→ 结尾结算或留白。骨架比镜头数更重要。
→ 分镜应有 `chapters[]`，一镜可以跨多段，但章节边界必须显式。

**M4｜长镜头不是罪，"无变化"才是罪。**
20–30 秒固定机位能成立，因为每一段都有新信息：新字幕、新数值、新光、新材质。**判据不是秒数，是有没有可读变化**（8–12 秒一次）。
→ 把 skill 的"一镜 4–8 秒"改成"变化间隔 ≤ 8–12 秒；镜长不限"。

**M5｜材质变奏 > 频繁切场景。**
四季转盘（同岛换四季）、绣布（像素=绣线）、ECG 地形（心跳=山）、唱片墙、窗户矩阵：**换材质比重建场景便宜，且更像"同一世界在变"**。
→ 分镜要写 `materialVariant`（同一构图的材质/季节/年代变体），并注明"变的是材质，不是机位"。

### 6.3 仍然没做的

1. **真实音频的拍点核对**：工具能给估计值，但"这段副歌是不是压在小节线第一拍"仍需人耳。

3. **点阵中文字模**：6×8 到 12×12 的中文字形需要手绘，脚本只烘 ASCII。

## 7. 一句话

这个号把 MV 做成了"**能被玩的东西**"：外壳是游戏/软件，情绪是数值，章节是界面页，字幕是台词。
原来的 skill 教人"把歌词演成一个任务"，这次复盘说明还差一层——**先定义那台机器，再让歌词去操作它**。

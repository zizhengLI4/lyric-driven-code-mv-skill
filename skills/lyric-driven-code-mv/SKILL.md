# 歌词驱动代码 MV

**所有新作默认采用《冬天又来临·四格相纸》的画风与制作规格。** 开始试片或整曲前，先打开[认可成片的六帧对照图](references/four-frame-photo-frames.png)，读[逐项制作基准](references/four-frame-photo-case.md)。按参考落实人物比例与表情、道具接触、空间层次、片头装潢、字幕、转场与应景音。新歌的地点、物件、人物经历和色彩重音由本曲歌词决定。用户明确指定其他风格时按其要求调整。

把歌曲情绪写成可观看的游戏演出：**歌词决定画什么，音乐决定何时强调。** 用人物的目标、行动、反馈和结果表达含义，进度条、道具和转场服务于这一因果链。

## 生成视频前，由用户确认场景与人物

新作或重做画面时，先从本次工程的实际绘制入口生成静帧，发给用户看。每个拟用场景标出编号、时段、对应歌词或器乐动机，以及画面里能看见的动作。每位主要人物并排展示全身远景和面部近景，保持同一造型。涉及坐姿、双人朝向或手与道具接触的镜头，另附对应构图。

分别询问场景与人物是否通过，等待用户明确答复，再启动任何视频生成或渲染（包括动态样片和整曲）。跳过动态样片、要求做整曲或认可其他歌曲的风格，都不能代替对本次静帧的确认。局部有修改意见就重出对应编号；已确认的部分沿用。后续更换场景设计或人物造型，先把受影响的静帧重新交给用户确认。

## 先做需求卡

新作先用一张简短的 `BRIEF.md` 定下三件事：**主题是什么、给谁看、结尾希望观众留下什么感受或印象**。再记录歌名/版本、歌词与音频路径、目标段落、画幅/帧率、字幕、现有素材、授权和交付范围。用户没有给全时，从歌曲和歌词提一个具体默认，并明确标成创作假设，不因缺少信息停住制作。

## 从歌曲到像素世界

1. **先建歌曲地图和听感笔记。** 校对录音版本和歌词，标出乐段、句子、能量变化、停顿、重复段落和需要强调的词。另用日常语言记下歌曲由什么感觉开始、哪里改变、最高点和结束时的余味，以及编曲变化带来的感受。听感笔记与 BPM、能量曲线等机器数据分开记录；未实际听过的部分标成待核对。用 `scripts/analyze-audio.mjs` 查看多频带瞬态与局部拍点候选；变速、静音或局部证据不足时保留空白，不把单一 BPM 外推成整曲拍网格。详细见 [音频与授权](references/audio-and-rights.md)。
2. **确定故事与像素美术方向。** 把主题、听感、歌词和人物目标连成一段可见旅程。沿用默认画风时，可先为同一段内容做 2–3 张静态方向图比较；用户已选像素风时，差异留在像素尺度、构图、光色和场景设计里，不切换成别的媒介。定稿后把角色比例、轮廓、色板、材质、光线、场景层次、字幕/UI 和转场规则记进 `BRIEF.md`。参考视频展示的方向是清楚统一的像素世界、持续行动的人物、随段落变化的地点/天气/光线，以及由事件触发的对话和状态 UI；不照抄其角色、旅程和具体高潮物件。
3. **让歌词推动单镜头事件。** 能画出的具体歌词优先转成对应物件或动作；抽象歌词用色彩、天气、角色表情/姿态、景别和留白转译。每镜围绕一个主视觉事件，写清动作、即时反馈和结果，避免一镜塞入多个不相关重点。结合听感笔记与音频能量安排画面强弱，歌曲实际最高点承担最有分量的构图或动作；如果副歌是最高点，让重复副歌带来更大回报或新后果，不强行套用烟花、闪白或某种固定高潮。
4. **按段落分镜和制作。** 先完成角色卡、场景/色板规则、歌曲结构表和关键段落分镜，再复用稳定角色与状态逐段制作。每次实现一段，检查通过后再扩展；局部问题只返修对应段落。同步预览列出镜头切点和明确踩拍事件的候选偏移、证据、置信值与建议时间；接受建议前由人工核对。歌词起点可与音乐网格不同。
5. **逐段复核后导出。** 视频样片可选；用户跳过时继续用代表静帧、角色动作条、分镜检查和工程预览。可用每秒一帧的接触表快速找字幕遮挡、主体越界和画面跳变，再对动作峰值/转场密集抽帧或播放核查。接触表不证明动作连续或卡点准确。导出后核对音视频流、时长、完整解码和关键画面；机器候选和静帧不等于人工听辨或最终成片验收。

## 从歌曲背景到人物与故事

新作或重写叙事时，只要人物或剧情有一项未指定，就主动使用当前助手的联网搜索工具，不要求用户先编故事。只指定人物，就保留人物、补剧情；只指定剧情，就保留剧情、补人物。两项都已指定，或只在已有工程上改字幕、混音、导出时，不启动这一步。

1. **认准作品。** 用歌名、词曲作者、演唱者及录音版本交叉检索，再查「歌名 + 创作缘起 / 访谈」和原语言关键词。区分原作背景与翻唱者的演绎；同名作品无法辨认且会改变剧情时再问版本。只搜索公开标识，不上传私人录音或未发行歌词；用户禁止联网时不搜索。
2. **查到可以引用的事实。** 打开创作者访谈、官方专辑说明或同期报道，不把搜索摘要当来源。在项目制作笔记记录标题、链接、支持的事实和采用它的镜头。没有来源把某段真实经历与作品联系起来，就不把它说成创作动机；歌词里的「我」也不自动等于歌手。
   定人物、立意和分镜前，打开同一录音版本的歌曲评论区，查看平台标为热门的公开评论。按[听众热评怎么入镜](references/research-and-story.md#听众热评怎么入镜)记录能解释歌词的听众视角，把选中的细节落实到镜头动作；无法读取时记录缺口。短试片同样执行。
3. **让背景推动行动。** 先用一句话串起主角的目标、阻碍、选择和结局，再随实际歌曲段落安排可见的行动与后果。默认可以用原创角色转译真实背景，明确区分事实与改编。例如，仅证实创作与迁居有关，可让虚构主角在主歌打包旧物、副歌试着寄回钥匙、尾声决定把钥匙留下。迁居有出处，钥匙是编剧的道具，不是真人轶事。
4. **接到成片。** 把人物写进 `actors`，把行动和后果写进每镜的 `objective`、`action`、`feedback`、`outcome`，并在对应 `scene.id` 的画法中实际呈现；重复副歌应看见前一次选择造成的变化。场景和人物静帧经用户确认后，按用户要求的范围进入渲染与验收，不停在背景摘要。无法联网或查不到可靠材料时，说明限制，按歌词或器乐情绪创作并标明「原创演绎，非真实经历」。

人物设定、研究记录与故事弧的详细模板见 [从一首歌到连续分镜](references/research-and-story.md)。目标效果是像素 RPG 地图、菜单、头像对白和有因果的状态 UI 时，读 [像素 RPG 文字制作案例](references/pixel-rpg-production-case.md)。从歌曲分析、逐阶段提示词到可选动态检查和交付，可继续读 [像素 MV 分阶段制作](references/pixel-mv-production.md)。已有成片出现角色、高潮、清晰度或转场问题时，先读 [进阶评审与定向优化](references/mv-review-and-refinement.md)，按同一量尺定向修改与复评。
用户指定《普通朋友》参考片、生活模拟 RPG、木框头像歌词或同款俯视地图时，采用[生活 RPG 风格与制作步骤](references/life-rpg-style.md)。其中包含可调用的对白面板、画面比例、晴雨回访和四条教程对应的分镜检查。

当参考是《麦恩莉》的街机双人叙事，或需要处理现实与关卡互切、重复歌词回访、动作接剪时，读[街机双人叙事与歌词接剪](references/arcade-duet-story.md)。将每次换景绑定到歌词中的动作、关系或段落变化，并在成片中回看切点两侧。

排分镜时沿歌词列出各段的地点、人物要做的事和观众第一次能看见的细节。尽量为新的行动创造不同场景，例如从站台等人、到街角拍贴店合照、再到家中把相纸贴上镜子，让同一件道具带观众走过不同地点。连续动作可以留在原地演完整。先选一个代表性地点和一个剧情道具，按[场景与道具的美术验收](references/pixel-game-visuals.md#场景与道具的美术验收)检查地点辨识、远中近景、材质光照和人物接触反馈，再扩整曲。

歌词中的心理变化需要观众读脸，或用户指定《time machine》式表情与动作质感时，按[像素人物的微表情与分层帧率](references/pixel-game-visuals.md#像素人物的微表情与分层帧率)制作独立近景脸、设计反应时序，并从实际镜头复核。

需要生成精细背景、设计前奏歌名或改善转场时，按[场景提示与片头设计](references/pixel-game-visuals.md#为生成背景和片头写场景提示)查阅同类视觉做法，写出可直接交给绘制工具的原创提示，并检查成片首帧和入戏动作。

用户认可人物与样片后再做整曲，先看[从认可的样片续成整曲](references/pixel-game-visuals.md#从认可的样片续成整曲)。所有新作均按[四格相纸制作复盘](references/four-frame-photo-case.md)关联片头、动作、回访和声音。若反馈提示音太小，到[提示音的可听度](references/sfx-and-beat.md#提示音的可听度)核查交付文件，并按用户指定的相对响度重新混音。

## 把歌词归纳成观众能读懂的主题

在选美术和道具前，用[从一首歌到连续分镜](references/research-and-story.md)里的「主题与可读性」方法写一句立意，给出开头、转折、结尾各一处歌词或音乐证据，再决定人物做什么。故事片要让观众从行动看懂关系、阻碍和结果；意象片可用同一意象的变化表达。把歌词字幕的语言、来源、时点和呈现方式写进制作记录。有人声、已有可用歌词的常规歌词 MV 默认制作为可读字幕；用户指定无字幕时遵照选择。时间或文字有疑问时标出待校范围。

## 工作流程

**先做依赖预检。** Pillow 只被 `scripts/` 下的 Python 脚本使用，声明在技能目录的 `requirements.txt`。先运行 `python -c "import PIL"` 检查并报告缺失；如确实需要安装，先向用户说明 `Pillow`、版本、用途和安装命令，得到同意后再执行，不把 `pip install` 放进自动预检。

Node 侧零第三方包：`scripts/`、`assets/scenes/`、`assets/templates/starter/` 下的 `.mjs` 只 import `node:` 内置模块，skill 目录内没有 `package.json`，**不需要 `npm install`，离线可用**——`validate-storyboard.mjs`、`hud-density.mjs` 同样如此。FFmpeg/FFprobe 是系统二进制，按第 4 步核对。

1. **固定需求和素材。** 确认主题、观众、希望留下的感受、歌曲版本、校对歌词、截取范围、画幅和交付范围，并记录在 `BRIEF.md`。自己找歌时先读 [音频与授权](references/audio-and-rights.md)，核对作品及录音的使用条件。分析参考片时先读 [参考片取证记录](references/reference-film-analysis.md)，分别记录可见事实、音频核对结果和实现推断。
2. **建立歌曲地图。** 标注句起止、段落、重音、留白、情绪与重复关系；统一成片坐标与原曲偏移。器乐配原创叙事字幕时说明文案角色，不当作演唱转录。`analyze-audio.mjs` 输出多频带起音、局部速度窗口和有来源标签的拍点候选；同步图只给有足够局部证据的镜头/动作建议。无法试听时保留草稿和具体待核对区间。
3. **先过角色辨识度，再选装置与场景。** 主要角色按实际景别制作轮廓、比例与姿态；两位及以上主角先做等尺度纯黑剪影对照。按[角色建模与表演](references/pixel-game-visuals.md#从角色设定到能表演的像素模型)把设定落实到实际绘制入口，逐帧检查关键动作的手、道具和支撑脚；去掉名字、配色和小道具后，仍须凭头部/服装轮廓、身形比例或姿态中的至少两类区分每人。群像最小实际显示尺寸和单人近景都要通过；失败时先重画角色，不靠换色、加小饰品或滤镜掩盖。
4. **先选装置，再选场景。** 先确定聊天、游戏系统、时间轴、计数器、章节牌、视角或材质舞台，再为每镜写目标→行动→反馈→结果。每句歌词先落到视觉账本：具体主体/物件、可识别特征、景别、准备→动作→结果、材质/光线；不能只给同一大场景换字幕。相邻四五句后检查是否需要换场景或推进内部事件，不机械一行一切。用 `chapters[]` 记录标题牌、关系阶段和结算；用 `scene.hud[]` 表达数值、状态、归零、损坏或失败的情绪反馈；同构图换季节、材质或年代时写 `materialVariant`。镜长由信息密度决定，不设固定上限；建议每 8–12 秒至少有一次可读变化，长镜头也可用于等待和留白。参考 [装置与章节](references/story-devices.md) 和 [HUD 与字幕](references/hud-and-subtitles.md)；要现成骨架时从 [装置模板](references/device-templates.md) 的五个 JSON（私信、读档、清单、结算、双轴滑块）里挑一个改写。反复意象安排首次出现、变化和再出现；重复副歌增加信息或后果。保留人物身份、装束和道具来龙去脉。以《普通朋友》成片完整的 00:00–01:06 开场演出作一个具体视觉例子：标题菜单进入地图，地点与天气推动段落变化，对话框、头像和关系/状态 HUD 贯穿角色行动；每项数值变化都接回触发它的人物行动，并在后续镜头保留状态。不要把参考缩成标题卡或装饰性 UI。细节见 [参考片取证记录](references/reference-film-analysis.md)、[像素世界与演出](references/pixel-game-visuals.md) 和 [像素 MV 分阶段制作](references/pixel-mv-production.md)。
5. **选择一种实现路线。** 沿用用户指定框架及现有工程。无框架且需要最小可运行工程时，复制整个 `assets/templates/starter/`；其中已包含共享核心与运行文件，复制后可独立运行 `node export.mjs --help`。HTML 动效工程可采用 HyperFrames，React 工程优先 Remotion。实现前读 [依赖与交付](references/dependencies-and-delivery.md)，列出必需项、已有项和可选项；安装包、下载浏览器/模型/字体、使用 API 或付费服务前先说明并沿用已有授权。
6. **样片作为可选质量关卡。** 新作品先建立角色卡/剪影表、关键帧接触表和原尺寸动作条。用户确认本次场景与人物静帧后，需要验证动态动作、镜头衔接或字幕时，可做约 10–15 秒样片；若有两位及以上主角，样片同时包含单人辨识镜头和群像镜头。明确跳过样片或只交 skill/方案/分镜时，用角色卡、静帧、分镜和时间/转场检查验收，不把视频样片设为前置条件。每句歌词仍须有可见焦点和动作结果；完整成片任务仍须通过最终渲染、解码与画面检查。分镜 JSON 作为时长、歌词、场景边界、转场及音乐状态的真源，代码按 `scene.id` 提供画法。每帧由时间直接求值，粒子固定种子。出口转场占前镜尾段，下一镜固定 `local=0` 预卷，不增加总时长。执行结构校验和 `scripts/qa.mjs` 的重复、逆序、乱序像素比较。
7. **扩展与验收。** 按用户范围推进到成片；已有样片时核对动作峰值、句尾、转场、歌词面板与摄像机边缘后再扩展。修改已有成片时先审片定位问题，只改对应镜头并定向复评；保留用户已确认的转场和画面决定。参考像素歌词视频时，在分镜顶层使用 `captionStyle.mode:"scene-panel"`，让浏览器预览、ASS 导出和章节牌保持同一套暖白/描边/像素面板参数；不提供时保留普通底部字幕兼容旧稿。导出后执行 FFprobe、完整解码、接触表和关键帧检查；具备播放条件时完整播放，逐项记录真实完成的检查。不能试听时交付 `draft`，明确待核对落点，不能声称音画已核对。

## 音乐证据与交付阶段

| `music.status` | 条件 | 交付义务 |
|---|---|---|
| `illustrative` | 自编时点、占位音轨或原创演示 | 开头显示“演示时点”，记录 `presentationNotice:true`；说明不是对应真实歌曲的对齐结果 |
| `draft` | 已有音频，机器分析或未经试听的标注 | `evidence.method` 写推定方法，`limitations` 写误差来源；`pendingChecks[]` 记录具体时间区间与未确认内容，允许交付草稿成片 |
| `verified` | 人工核对了相关音频、歌词与关键落点 | 记录 `evidence.reviewer`、含时区完整时间戳 `reviewedAt`（如 `2026-11-17T08:00:00Z`），交付说明写核对范围 |

自动分析不能升级为 `verified`。逐字时点按句长均分时，字幕说明为视觉填充；BPM 的半速/双速歧义、伴奏起音、拖音及源偏移均可能造成误差。缺少音频时先交付 `illustrative` 分镜或演示，不因无法试听无限等待。状态与授权是两项独立条件，草稿状态不能代替发布许可。

## 像素构图与模板

像素场景按背景、装饰/光晕、主体、前景遮挡绘制；检查主体占比、亮度和单色面积，再抽帧检查实际结果。角色剪影、字幕安全区、图层顺序与调色建议见 [像素世界与演出](references/pixel-game-visuals.md)。

无既有工程且需要可运行骨架时，复制整个 [starter 模板](assets/templates/starter/README.md)。starter 默认画面仅验证色块/网格、摄像机、转场、字幕和导出，不是美术样片；实现作品前须按项目替换默认画面。`assets/storyboard-example.json` 用于了解分镜字段，不规定故事或美术。使用已有框架时沿用其渲染入口。运行命令、路径、安全规则与导出清单以 starter 说明为准；新建文件保存到视频工程目录，不在 Skill 安装目录运行写入型命令。

## 按需打开详细流程

- 时间坐标、歌词数据与词级时间格式见 [时间与分镜](references/storyboard-and-timing.md)。LRC 转换仍以整句为单位；使用可选 `lyrics[].words[]` 时，每词提供 `{text,start,end}`，按顺序拼接后须精确等于 `zh ?? text`，时点采用成片秒。预览与 ASS 导出使用同一组时点；词界来自实际核对，均分只作为视觉填充。
- 音频分析、BPM 证据与授权检查见 [音频与授权](references/audio-and-rights.md)。镜头、歌词和候选节拍同轴检查见 [同步候选图](references/sync-review.md)。
- 分镜 schema、转场预卷和确定性 QA 见 [时间与分镜](references/storyboard-and-timing.md)；HUD/字幕排版和安全区见 [HUD 与字幕](references/hud-and-subtitles.md)。
- starter 的 LRC 导入、音效、预览、字幕及 FFmpeg/FFprobe 导出检查见 [starter 说明](assets/templates/starter/README.md) 与 [依赖与交付](references/dependencies-and-delivery.md)。
- 音效事件和人工试听边界见 [音效与卡点](references/sfx-and-beat.md)。

制作整曲前，从项目实际渲染入口取三个代表镜头：两个不同地点各一帧，一个人物反应近景。遮住文字与手持道具，检查能否从建筑结构、空间纵深或家具布局辨出两地，从眉眼、嘴形和视线读出反应。若两地共用同一底图且只替换前景，或近景只放大远景人物，先重绘对应资产，再扩整曲。导出后在一句实际演唱的位置检查歌词正文与时点；章节短句单独验收。

**角色原创与坐姿验收。** 从参考片继承像素尺度、明暗分层和表情可读性。新歌先为角色另画发型轮廓、脸型或五官、服装剪裁和职业细节，远近景各画一帧对照。座面与地板都入镜时，用独立坐姿画出臀部承重、大腿向前、膝部转折、小腿和鞋底，并在成片尺寸核对座面与地面的接触。胸像只用于画框或有明确前景遮挡的近景。双人镜头写明谁先看谁、对方何时回应。导出后核对每镜起中末三帧，接触、转身或落座另看连续帧；任何悬空、残脸入画、朝向冲突或道具提前出现都先回到绘制入口修改，再导出复核。

## 完成标准

- 去掉字幕，动作仍能说明每句的具体含义；主体、道具、接触与结果都可读，HUD 变化可追溯到行动。
- 细节与精致度通过材质、光向、遮挡、角色特征和次级动作体现；不靠抽象装饰、背景铺陈或噪点填满画面。
- 主要角色在纯黑剪影、最小群像尺寸和单人近景间仍可辨，不只靠颜色、姓名牌或小道具识别；单人近景使用独立细节资产，不把低分辨率群像精灵直接放大。
- 把每镜一帧的缩略图按整曲顺序铺开，重点并排比较两次副歌。回到旧地点时，画面应让人看出上次行动留下的结果，例如上次两人拍照，这次只剩一人来取相纸。若只是换色、推近或换字幕，仍按同一地点检查；多个段落反复使用同一背景又没有新的剧情信息时，重排到能承接下一步行动的新场景。
- 同帧重复和乱序求值一致，首尾、每镜及转场没有状态漂移；摄像机移动不露黑，字幕清晰。
- 字幕底边与 HUD 都在平台安全区内：用 `safe-area.py` 叠一帧确认，别只看成片。
- `hud-density.mjs` 报出的最长空窗不超过 12 秒；超过就先补变化，别加镜头。
- 每条音效选择 visual/beat/free 锚点；起点 at 与落点 hitAt 含义清楚。混音后检查峰值，音效来源及同步结论不超出验证证据。
- 成片音视频流、时长、画幅和帧率正确；音乐证据状态及实际检查范围写清楚。
- 交付可编辑源文件、分镜与分析数据、资源来源/许可/署名、所选依赖锁文件（使用依赖时）、成片和简短验收记录。仅请求报告、分镜或草稿时交付对应阶段，不擅自扩展整曲。

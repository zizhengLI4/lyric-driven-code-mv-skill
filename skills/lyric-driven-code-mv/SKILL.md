# 歌词驱动代码 MV

歌词决定画什么，音乐决定何时强调。把听到的意思写成能看见的目标、行动、反馈和结果，再决定景别、道具与界面。

## 需求、风格与工具

在项目的 `BRIEF.md` 记录歌名与录音版本、可用歌词、原曲偏移、片段或整曲范围、画幅、帧率、字幕、已有工程、目标观众和期望结尾。区分已确认、待核查与创作假设。沿用已选风格及现有渲染入口。风格未定且适合像素叙事时，可打开《四格相纸》或其他对应的[制作案例](references/production-cases.md)。用户指定水彩等其他风格时，按指定方向做本曲静帧；仅在用户选用某案例时打开其对应图片。搭建新工程可复制整个 [starter](assets/templates/starter/README.md)。它的默认色块网格用于技术检查。

从 Skill 目录运行 `node scripts/check-environment.mjs --missing-only` 核对 starter。需要其他渲染路线、字体、Python 或排障时读[依赖与交付](references/dependencies-and-delivery.md)。用户指定 Remotion 时，选用 [Remotion 路线](references/remotion-mv.md)和共用分镜、字幕、确认与验收流程。使用项目歌曲，默认 1920×1080、30 fps、中文字幕，无旁白。缺少导出依赖时，可继续分镜、静帧或其他已有工具支持的工作；说明交付范围。追加安装或付费服务前说明用途与所需权限。

## 研究与歌曲地图

新作或重写叙事时，用户没指定人物或剧情，就在用户允许联网的范围内检索作品身份和背景。核对实际录音版本，优先实际读到的创作者访谈、官方发行说明或同期报道。保留用户已给的人物和剧情。只改字幕、混音或导出时沿用项目记录。把来源与采用位置写进制作笔记，区分外部事实、推断和原创改编。需要分析参考片或编排代码绘制提示时，读[歌曲研究、参考片取证与代码绘制](references/research-and-story.md)。

公开热评按需查看，仅使用实际读取的同版评论。没读到正文时，不得声称看过、引用或转述；记录访问缺口并继续。离线或没有可靠背景时，按歌词和器乐情绪设计，交付说明写明检索缺口与「原创演绎，非真实经历」。作品没给出创作缘起时，把人物行动写作原创设定。

固定源音轨起点，记录歌词句界、拖音、留白、段落与重音。用 `analyze-audio.mjs` 生成多频带起音和局部节拍候选；记录实际试听区间、半速或双速歧义和待核点，防止用同一输入循环验证拍点。按[音频与授权](references/audio-and-rights.md)检查来源、用途和证据。字幕时间与分镜统一用成片秒。LRC 转换仍以整句为单位；可选 `lyrics[].words[]` 中每词为 `{text,start,end}`，拼接应精确等于 `zh ?? text`。预览与 ASS 使用同一时间组，均分只作为视觉填充。排版见 [HUD 与字幕](references/hud-and-subtitles.md)。

## 从歌词到可画的行动

先用一句话串起目标、阻碍、选择和结局。给角色设 `actors` ID，逐句写物件、可见行动、状态反馈、结果和前后关系。对应镜头的 `objective`、`action`、`feedback`、`outcome` 必须落实在实际绘制的 `scene.id`。需要界面时，从[叙事装置与模板](references/devices.md)选可表达行动后果的部件。分镜字段、分阶段工作和转场时基见[时间与分镜](references/storyboard-and-timing.md)。镜头区间用 `[start,end)`，starter 的 `designT` 是画法内部的 0–6 秒设计时钟；接事件前先换算回实际成片时间或镜头局部秒。

像素作品按[人物、像素画法与 RPG 案例](references/pixel-visuals.md)检查灯光、材质、遮挡与表情。原创角色在纯黑剪影、群像远景和原生脸部近景应可辨；近景使用独立细节。坐姿画出座面支撑和脚底落位，转身、对视、递物按动作顺序画准备、接触与反应。回访旧地点和重复副歌时，让前次行动留下可辨的东西。沿歌词变化安排有用途的新地点，避免只靠换色或推近。

## 先确认静帧，再制作动态

从本项目实际绘制入口生成正式尺寸静帧。按[审片与验收](references/review-and-acceptance.md)先逐场逐人自检，再交全部拟用场景的编号、时段、歌词或器乐动机、可见动作，及每位主角的全身远景、原生面部近景和本曲用到的表情。坐下、转身、对视、递物或接触另附动作条。片头至少取标题、第一次行动与开唱三处。

分别记录用户对场景和人物的明确确认及范围，绑定当前分镜、绘制文件及静帧。新增或改动设计时重出受影响项，沿用未改项目的确认。两类确认齐全后，按需求选做动态试片或直接做整曲。使用 starter 或最小 Python 渲染时传 `--review`；其他入口在动态出帧或编码前调用同一检查器。扩展已确认的试片时复核接缝，再确认新增场景和人物。

## 音画与成片验收

分镜 JSON 统一时长、歌词、镜头边界、音乐与转场。每帧只按时间与固定种子求值。用 `validate-storyboard.mjs` 核结构，用 `qa.mjs` 核同时间重复和乱序求值。按[音效与动作卡点](references/sfx-and-beat.md)定义 `visual`、`beat` 或 `free` 锚点、`at` 和 `hitAt`。只卡重音时，对连续动作的每一下分别标出原曲可听重音与可见结果，先关闭新增拟音按原速复核。原曲和画面决定哪里留白、哪里单击或连击。导出后核混音的听感、电平、事件窗口及真峰值。

- `illustrative` 用于演示或占位。片头显示「演示时点」，记录 `presentationNotice:true`。
- `draft` 用于机器候选或未经试听的时点。写明 `evidence.method`、`limitations` 和有具体时间区间的 `pendingChecks[]`。
- `verified` 需要实际人工核对相应音频、歌词和关键落点，记录 `evidence.reviewer` 与带时区的 `reviewedAt`，交付说明注明核对范围。机器比对通过不改变人工核对状态。

逐镜看起中末、转场两侧、每次副歌和片尾。对承重、道具触点、表情或双人视线再密查连续帧。遮字幕检查叙事，再核歌词、音画时点与手机阅读安全区；用 `safe-area.py` 叠图。对 `hud-density.mjs` 提示的超过 12 秒空窗，结合实际动作判断是否需要改动。交付前用 FFprobe 核时长、画幅、帧率和音视频流，用 FFmpeg 完整解码并核查代表帧。按用户指定范围交付可编辑源文件、分镜、分析、素材署名与许可、依赖锁文件（如适用）、成片及验收记录。

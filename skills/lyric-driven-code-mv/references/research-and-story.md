# 从一首歌到连续分镜

适用：用户只丢来一个歌名/音频，没给人物也没给故事；或只给了人物、只给了剧情。
这一步的产物是**可校验的考据记录 + 人物卡 + 故事弧 + 连续分镜表**，不是"感觉一下这首歌讲什么"。

## 一、先判定入口，别问第二遍

| 用户给了什么 | 保留 | 要补 | 不许做 |
|---|---|---|---|
| 只有歌曲（或歌名） | 歌曲、版本、时长 | 创作背景考据 → 人物 → 故事 → 分镜 | 不要反问"你想要什么故事"；不要把歌词逐句直译成画面 |
| 歌曲 + 人物 | 人物 ID/外观/装束/关系 | 故事与分镜；考据只补人物所处世界的细节 | 不要换掉人物的外观或关系 |
| 歌曲 + 剧情 | 事件、结局、关键动作 | 人物功能位与外观；考据只补动机的合理性 | 不要改结局，也不要删用户给的关键动作 |
| 歌曲 + 人物 + 剧情 | 全部 | 只补分镜与实现 | 不要"优化"用户已确认的设定 |
| 没有歌，只有人物/剧情 | — | 先要音频或明确做无歌词版；无歌词版按分镜时间轴写旁白/字幕 | 不要凭空假定一首歌的时长与段落 |

缺什么补什么，已有的一个字都不动。补完直接进 [分阶段制作](pixel-mv-production.md) 的 B 阶段，不重走 A 阶段。

## 二、联网考据：查什么，记什么

先声明要联网，然后按下面四组查。每组至少一条独立来源；同一 claim 有两处以上互相印证才升为"事实"。

| 组 | 查什么 | 典型来源 | 用来干什么 |
|---|---|---|---|
| 作品身份 | 歌名、歌手、发行年、专辑/单曲、词曲作者、是否翻唱/采样/致敬 | 音乐平台曲目页、唱片公司页、维基/百科、版权登记信息 | 决定标题牌、年代感、片尾署名 |
| 创作意图 | 歌手/作者访谈、创作手记、专辑文案、直播或播客里的自述 | 官方访谈、杂志专访、官方社媒 | 决定故事的**真问题**（写给谁、为什么写） |
| 外部世界 | 歌词里的人名、地名、方言、行业、时代事件、器物 | 地方志/地图/博物馆/新闻档案 | 决定场景、道具、HUD 的单位 |
| 接受史 | 乐评、高赞评论、官方 MV 的视觉母题 | 乐评站、官方 MV、平台热评 | 决定母题与"观众已经在期待什么" |

记录格式（写进工程 `research.md`，同时落进分镜 JSON 的 `research` 块）：

```json
{
  "status": "verified",
  "song": { "title": "歌名", "artist": "歌手", "released": "2021", "writers": ["词作者", "曲作者"] },
  "sources": [
    { "url": "https://example.com/interview", "title": "歌手访谈：这首歌写给谁", "retrieved": "2026-11-18",
      "claims": ["写给他去世的祖母", "副歌的人声采样来自 1998 年的磁带"] }
  ],
  "facts": [
    { "claim": "写给他去世的祖母", "sourceIndex": 0, "confidence": "fact" },
    { "claim": "磁带是童年夏天的录音", "sourceIndex": 0, "confidence": "inference" },
    { "claim": "年代定在 1998 年的南方小城", "confidence": "creative" }
  ],
  "gaps": ["没有查到官方 MV，视觉母题按歌词内部证据设计"]
}
```

- `confidence` 只有三档：`fact`（来源直说）/ `inference`（你从来源推的）/ `creative`（你的设计）。**三档必须分开写**，否则后面会把设定当成史实讲给用户。
- `status`：`verified`（≥2 条来源且关键 claim 有印证）/ `partial`（只有作品身份）/ `unverified`（没联网或查不到，全部按歌词内部证据做）。
- 查不到就写进 `gaps`，并在交付说明里重复一次。不要用"据悉""据说"填空。

### 听众热评怎么入镜

先打开用户给的曲目页，核对录音版本，再看其热门评论或平台为该曲公开返回的热评列表。记录平台、链接或评论 ID、查阅日期及实际读到的范围。评论区未开放、仅显示最新评论、或没有相关内容时，如实写入研究缺口，继续用歌词和已有背景设计。

读热评时留意听众对哪句歌词有反应、想起了哪种日常经验，以及是否有人听出了另一种意思。筛掉互动玩笑和无关留言。用自己的话记下有画面价值的观察，保留个别观点的范围；点赞数仅用于说明排序。有关作者私生活或写作缘起的说法回到访谈、创作手记查证。

在制作笔记和分镜 research 中把采用项串起来：评论定位 → 听众理解 → 对应歌词或留白 → scene.id 与观众实际能看到的动作。可取一个手势、停顿、道具用法或回访方式。评论和歌词有张力时可保留张力；没有合适项就说明理由。用虚构角色重写可见细节，保护评论者身份，避免把个人故事直接搬上字幕。

### 三条硬规则

1. **歌手的人生不等于角色的人生。** 考据只用来定"真问题"和世界的质感；角色另起 ID、另设外观。直接把歌手本人当主角，会把 MV 变成纪录片。
2. **官方 MV 是参考片，不是分镜模板。** 要拆就按 [拆一支参考片](reference-film-analysis.md) 采样 ≥12 帧、分事实/测量/推断三级；不能把它的镜头顺序当自己的分镜。
3. **歌词是证据，不是剧本。** 一句"我等了很久"可以写成倒计时归零、存档读档失败、车站时钟跳变；不要画一个人站着望天。

## 三、从考据到人物：只设四个功能位

任何故事都只需要四个位置。用户给了人物就把他/她放进对应位置，缺的位置补人，不要新增第五个主角。

| 功能位 | 必须回答 | 在 MV 里的可见形式 |
|---|---|---|
| 想要的人（主体） | 想要什么、愿意付出什么 | 主动作：完成任务、修复物件、发出消息、写入存档 |
| 挡住的人/物（阻碍） | 用什么挡、挡得多具体 | 锁住的门、断开的连接、时间限制、缺少资源 |
| 见证的人（对手/同伴） | 看见什么、误以为什么 | 同伴的表情、系统提示、告示牌、聊天框里的"对方正在输入" |
| 世界规则（装置） | 能不能见面、有没有时间戳、谁在看 | 从 [叙事装置](story-devices.md) 选 1–3 个，写下"规则" |

人物卡（写进 `BRIEF.md`，字段与分镜 `actors[]` 对齐）：

```text
p1 主体 · 外观：短发 / 宽肩外套 / 站高 18px（虚拟网格）/ 朝右 / 持物点右手
    欲望：完成当前目标      代价：剩余时间或资源减少
p2 同伴 · 外观：长发 / 短斗篷 / 朝左 / 无持物
    欲望：帮助主体推进任务  误认：把系统提示理解成最终结果
rule 装置：按统一规则更新任务状态；已持有的道具跨镜保留
```

小精灵在 18–24px 时优先控制三类显眼信号：头部/发型形状、衣身/体态形状、稳定识别物；颜色只作辅助。去色并移除小道具后，至少仍有两类形状特征能区分角色。近景卡可细化脸部、材质和叙事细节，不把小精灵的信息预算套到近景。完整门槛见 [角色差异度与完成度](pixel-game-visuals.md#角色差异度与完成度门槛)。

## 四、从人物到故事弧：三幕压到歌词句组上

把歌词按"谁在说话、想要什么变了没"切成 3–5 个句组，一个句组就是一幕。不要按每句一幕切，那是字幕 PPT。

```text
幕1（句组 A，约 0–35%）：立起欲望与阻碍。第一次行动，第一次失败。
幕2（句组 B，约 35–70%）：代价显现。重复副歌在这里必须给出新信息（新证据/新后果），不是复读。
幕3（句组 C，约 70–100%）：结局。成功、失败或尚未完成但留下了可见后果；留白句交给画面，不加旁白。
```

每幕写一行因果，格式固定：**目标 → 行动 → 反馈 → 结果**。四段缺一段就是空镜。

- 反馈必须落在画面上：数值变了、路线断了、灯亮了、档坏了。
- 结果必须改变下一幕的起点，否则删掉这一幕。
- 结局可以在歌词里没写；允许"未完成"，但要有可见的代价留下。

## 五、从故事弧到连续分镜

"连续"指同一件东西跨镜不消失、同一处伤不自己好、同一套规则不破例。落地成 `scenes[]`：

1. **镜头 ID 用语义命名**（`send-and-stop`、`other-bank-sees-light`），不用 `shot1`；改动时靠 ID 定位影响范围。
2. **镜间不重叠不留洞**（`end` 必须等于下一镜 `start`）；切点只允许在句边界或重音上，不在字中间。
3. **每镜必须有事件**：至少一个 `events[]` 或一次道具变化，否则抽帧看不到变化（校验器会给警告）。
4. **跨镜连续性三件套**：道具持有者、人物位置、HUD 当前值。写进 `outcome` 和下一镜的 `objective`，让它在文字上就连续。
5. **重复段落加信息**：第二次副歌可以换视角、展示新证据或增加代价；若结局发生变化，应由歌词与人物行动支持。
6. **每 8–12 秒一次可读变化**（HUD/字幕/动作峰值/材质），用 `hud-density.mjs` 量，不靠感觉。
7. **出口转场写清楚**：`exitTransition` 记录镜头如何离开以及哪些状态要延续。例如横向移动时保留人物位置和当前道具状态，让下一镜接得上。

分镜写完先跑：

```sh
node scripts/validate-storyboard.mjs --strict path/to/storyboard.json
node scripts/hud-density.mjs path/to/storyboard.json --max-gap 8 --strict
```

两条都过，才进 B 阶段静帧。校验器不证明歌词语义正确，只证明结构与记录完整。

## 六、反面清单

- 把歌词逐句配一张图：15 句 15 个场景，观众只看到字幕换背景。
- 用考据到的歌手生平直接当剧情：主角变成"歌手的替身"，人物卡失效。
- 人物只写"忧郁少年"：18px 里读不出来，画出来每帧都一样。
- 结局靠旁白说：字幕写"他终于放下了"，画面什么都没变。
- 母题首尾失去联系：开场反复出现的物件，在结尾突然被无关元素替换，观众难以读出呼应。
- HUD 没有单位：`数值 87`、`进度 100%`，读者不知道 100% 是什么满了。

## 主题与可读性

1. **归纳原作。** 在歌曲地图上挑出开头的处境、转折处改变的事实、结尾仍未解决或已经改变的事。每条记一个词句或可定位的音乐变化。重复句合并记录，同时注明第二次出现前听众多知道了什么。把叙述者、被唱到的人、时间顺序和明显歧义区分开。
2. **选择解释。** 写一句对作品的具体理解。若只能写出“爱、遗憾、成长”，追问“谁想要什么，两件事为什么不能同时得到，最后怎样面对”。有两种可信解释时，用最难解释的那一句歌词检验各自的解释。歌里没有给出的离别原因、职业和结局都标为原创改编。器乐或开放式作品可保留多义，写清观众应察觉的情绪变化。
3. **翻译为画面。** 在草图中并排放开头、转折和结尾，给每张各写一句只描述可见动作的话。开头交代关系与眼下的问题，转折让一个决定产生后果，结尾回到开头的具体事物并改变它的用途。例如，开头摆两套餐具，离别后每天照摆，结尾终于为自己热了一顿饭。示例中的道具按歌曲另选。
4. **检查场景是否够用。** 逐段问“观众在这里新知道了什么”。同样的地点能承载不同决定；只有取景或字幕在变时，合并空转镜头，或补上缺失的行动、对方的反应、具体后果。副歌重现时核对它是否推进了先前的选择。
5. **交付前复评。** 先暂时隐藏歌词和剧情说明，看首段能否认出关系、在关键动作之后能否辨认改变、从尾镜能否推回立意。再恢复歌词，检查歌词和画面是否相互支持，以及演唱字幕和原创对白能否区分。若没有独立观众参与，记录为作者自检。若难以读懂，先返修提供线索的镜头。

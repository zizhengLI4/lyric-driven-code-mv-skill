# HUD 与字幕形态

## 安全区

字幕和 HUD 的位置按 `scripts/safe-area.py` 的输出线判定，不按记忆里的旧数字。脚本只在这里定义平台边距，别处出现的数值以它为准。

| 1920×1080 | 安全线 | 来源 |
|---|---|---|
| 底边 | ≥ **92 px**（字幕与 HUD 最下沿 y ≤ 988） | `h - int(h * 0.085)`：`0.085 × 1080 = 91.8`，`int()` 截断得 91，线画在 y=989；阈值向上取整到 92 |
| 右侧 | ≥ 124 px（最右沿 x ≤ 1796） | `w - int(w * 0.065)`：`0.065 × 1920 = 124.8`，`int()` 截断得 124，线画在 x=1796 |
| 顶部 | 118 px 高的标题/搜索区不放关键读数 | `int(h * 0.11)` |

- **92 px 是硬下限。** 60–90 px 是作废的早期参考值，按它排的字幕一叠加就判越界、整版重渲。真实案例：基线 y=1002（到画面底 78 px，算上描边后底边只剩 62 px），当时按「60–90」区间判断，用 `safe-area.py` 一叠就废。
- **底条、描边、背景整体计入字幕高度。** 量的是最外层像素，不是文字基线：底板底边、描边外沿、黑底条都属于字幕高度；只按基线判断会漏掉这十几像素。
- 换分辨率按同一比例重算，不要照抄 1080p 的数字：720p 底边 ≥ 62 px（`ceil(0.085 × 720)`），1440p ≥ 123 px，竖屏 1080×1920 ≥ 164 px。
- 判定动作：`python scripts/safe-area.py --overlay work/frame_00120.png -o work/checked.png`，或 `--video work/silent.mp4 --at 3 10`；橙色斜线压到字幕或 HUD 就是越界，改完重抽同一帧确认。
- 成批查版式用 `layout-check.py`，`--safe "right=124,bottom=92"` 与上表一致，`--subtitle-band` 传含底条的最外层矩形。

## HUD 设计

用“行动 → 反馈 → 结果”检查每个 HUD：人物做了什么，哪一个值改变，改变之后观众知道什么。优先选择能承载剧情的单一指标；需要多个指标时让它们使用不同量纲，例如天数、次数和百分比分别表达时间、重复和修复程度。

负向状态是可用的叙事结果：归零、下降、损坏、失败和反讽值可以比成功条更有信息。`scene.hud[]` 中的 `type`、`label`、`value`、`min`、`max` 和 `meaning` 用于记录这一意图。`value` 使用非空字符串或有限数；`bar` 需要数值 `value/min/max` 且满足 `min < max` 与 `min <= value <= max`。负值可由负的 `min` 表达。校验器只检查结构和可解释性，不判断美术是否有效。

## 字幕变化

根据画面和阅读距离选择字幕形态：

- 中英上下或左右分栏：同一信息的双语阅读；
- 黑底条或半透明卡：复杂背景、聊天记录和通知；
- 符号前缀（如 `♪`）：明确这是歌曲/语音/系统日志的文字角色；
- 竖排：国风标题或窄屏信息；
- 单字散点：只在动作确实需要逐字节奏时使用。

`lyrics[].text` 是默认文字，`zh`、`en` 可用于字幕层。原创叙事文案不要写成歌手演唱的逐字歌词；没有试听时保持 `music.status:"draft"`，在 `pendingChecks[]` 写清待确认范围。

字幕不需要每次踩拍。只对明确标记 `event.sync:"beat"` 的事件做候选拍点检查，其他字幕可按语义、句尾和阅读时长安排。

## 单行字数

`lyrics[].text` 去掉所有空白后的**显示宽度**不超过 **22 个全角字宽**。全角字符（汉字、假名、全角标点）算 1，半角字符（ASCII 字母、数字、半角标点）算 0.5——一行 40 个英文字符只占 20 个全角宽，排得下。

按字符数直接数会误伤纯英文字幕：早期实现数 `[...text].length`，于是一行 37 个英文字符被判成超限 15 个字。校验器现在按宽度算，诊断文字写的是「23 个全角字宽」。

超出就按语义拆行，不按固定宽度硬切。拆分优先级：`，。！？/` → `、` → 虚词前。

## 两条用真实成片打回来的教训

**1. 文档写了 92px，代码写的 0.07，两边各说各话。**
`margin = Math.round(height * 0.07)` 在 1080p 上是 76px，实测成片字幕最下沿落在 y=1000、距底仅 **79px**，直接踩穿 92px 安全线。文档反复强调 92px 完全没起作用——因为渲染器根本没读文档，它自己算了一个别的数。
修法：`Math.ceil(height * 0.085)`，1080p → 92，720p → 62，1440p → 123。用 `ceil` 不用 `round`，舍入方向朝更安全的一侧。
**验证方式不是读代码，是量成片**：抽帧转 `rgb24` 原始像素，找亮像素在下半部的最下沿，算它到画布底的距离。改前 79px，改后 95px。

**2. 切点、歌词、场景事件是三套需要各自吸附的时间。**
只把切点吸附到拍点、只把歌词吸附到起音，画面里的事件（灯灭、反光、影子拉长）仍然按旧网格排着，实测 37 个标记 `sync:"beat"` 的事件最大偏离 192ms。观众看到的是这些事件，所以"卡点没卡上"和"意义不明的画面"是同一个病：**声明的同步关系没有在每一层都落实**。
重排顺序：切点 → 歌词 → 场景内事件 → chapters/sections 边界，最后跑 `validate-storyboard` + `timeline-sync --align beats` 复核。

拆行优先级，从左到右依次尝试：

1. 句子标点 `，` `。` `！` `？` `/` 之后；`/` 本身就是手写的分行标记，直接在处断；
2. 顿号 `、` 之后；
3. 虚词之前（`的` `了` `是` `把` `让`），让虚词留在下一行开头。

拆完每行都要重新过安全区与字号，单行变短不等于可以下移。自查：

```sh
python -c "import json,re,sys;d=json.load(open(sys.argv[1],encoding='utf-8'));[print(len(re.sub(r'\s+','',t['text'])),t['text']) for t in d.get('lyrics',[])]" storyboard.json
```

输出每行的字数与原文，`> 22` 的行逐条改到 22 以内。校验器对超长行给出定位警告，但不会替你拆行。

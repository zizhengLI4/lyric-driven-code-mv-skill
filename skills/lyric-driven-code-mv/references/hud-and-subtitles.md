# HUD 与字幕形态

## HUD 设计

用“行动 → 反馈 → 结果”检查每个 HUD：人物做了什么，哪一个值改变，改变之后观众知道什么。优先选择能承载剧情的单一指标；需要多个指标时让它们使用不同量纲，例如天数、次数和百分比分别表达时间、重复和修复程度。

负向状态是可用的叙事结果：归零、下降、损坏、失败和反讽值可以比成功条更有信息。`scene.hud[]` 中的 `type`、`label`、`value`、`min`、`max` 和 `meaning` 用于记录这一意图；校验器只检查结构和可解释性，不判断美术是否有效。

## 字幕变化

根据画面和阅读距离选择字幕形态：

- 中英上下或左右分栏：同一信息的双语阅读；
- 黑底条或半透明卡：复杂背景、聊天记录和通知；
- 符号前缀（如 `♪`）：明确这是歌曲/语音/系统日志的文字角色；
- 竖排：国风标题或窄屏信息；
- 单字散点：只在动作确实需要逐字节奏时使用。

`lyrics[].text` 是默认文字，`zh`、`en` 可用于字幕层。原创叙事文案不要写成歌手演唱的逐字歌词；没有试听时保持 `music.status:"draft"`，在 `pendingChecks[]` 写清待确认范围。

字幕不需要每次踩拍。只对明确标记 `event.sync:"beat"` 的事件做候选拍点检查，其他字幕可按语义、句尾和阅读时长安排。

# 像素世界与演出

## 世界与身份

先定人物身份、轮廓、装束、所在地、共同意象与道具用途。角色 ID 表示身份，服装表示状态；用发型、轮廓、章节标记和连续镜头保持可识别性。复用地图块、室内模块、精灵动作、HUD 和粒子，把时间放在语义与镜头上。

思念可以成为信件，真心成为收集后填满的心，保留成为物件上架，等待成为迟迟未满的进度，距离成为中断的路线。数值先有叙事意义，再决定样式和关键帧。可观看演出的菜单、碰撞、加分和连接可按时间预排，无需实现真实网络或游戏系统。

## RPG 界面作为叙事因果

《普通朋友》00:00–01:06 的开场由标题菜单进入俯视地图，再以宅地、街道、夜雨、暗场探索和海边栈桥连接人物互动。暖色对话框和固定头像贯穿交流，关系心形、递增计数与双竖条状态变化出现在不同情节段落。此序列提供的是界面、场景和情绪变化共同叙事的可见例子，具体 UI 更新与角色选择之间的因果关系属于本项目可采用的设计规则。

设计时为每个界面字段写清四件事：**当前显示什么状态 → 哪个角色行动/事件触发变化 → 镜头里如何看见变化 → 后续哪一镜继续承接该状态**。例如，人物完成一次互动后，关系图标才改变；同一街道进入夜雨时，环境和对话共同表现关系变化；黑暗探索期间的计数与双竖条变化连接到明确的探索动作；来到海边后保留前段状态或刻意重置，并在分镜中说明原因。菜单选中后进入地图、任务计数增加、状态归零或损坏也遵循同一因果要求。

HUD 是画面叙事的一部分，应跟随可见行动和事件更新；状态变化沿着分镜因果推进。删去 UI 后动作仍要表达核心意思；只在情节需要时显示或强调数值，变化后维持一致的角色、地点与状态。对白、头像和系统反馈分层清楚，避免多个文本框争夺同一注意力；不采用的数字、名字或教程式屏幕录制文字不要塞入成片。

### 角色差异度与完成度门槛

角色质感来自受控的轮廓、比例、姿态和材质细节，不是给同一模板换五种颜色。每个主要角色建立角色卡：叙事功能、头部/发型轮廓、身形比例、服装外轮廓、常用姿态、主色/点缀色、稳定识别物和持物锚点。颜色与小道具只能作为辅助线索，身份核心至少有两个不依赖颜色的形状特征。

质感按“大形→色块→材质光影→少量识别细节”逐层完成。布料用方向明确的褶皱和克制高光表现硬挺或垂坠；头发用成组发束与边缘亮面；皮革、金属或镜片用少量高对比反光块。全员遵守同一光源方向与像素簇尺度，角色之间可用不同材质响应与明暗分组区分。细节必须在目标输出尺寸可读；不靠整层噪点、模糊、过度锐化或堆饰品制造“高级感”。

**剪影盲测：**把角色同尺度并排，隐藏姓名、颜色和小道具并填成纯黑。每人至少凭头部/服装轮廓、身形/重心、姿态这三类中的两类与他人区分；恢复配色后，再在群像的最小实际显示尺寸下复核。两人仍像同一个模板时，先改轮廓、比例或姿态，不用加滤镜、噪点或姓名牌掩盖。

主要角色应分别提供小比例群像精灵与较大近景资产；不能把小精灵直接放大冒充细致特写。近景保持同一像素网格、光源方向和色彩分组。通过条件是：黑色剪影表、最小群像、单人近景和动作样片（如需）中都能认出同一角色。仅交付静帧或分镜时，用剪影表、关键姿态和尺寸对照复核静态辨识度；动作连续性在动态验证或成片检查中确认。参考片只借鉴“剪影对比强、姿态有性格、细节受控”等原则，不复制具体脸型、服装组合、配色或站位。


#### 从角色设定到能表演的像素模型

- **先画结构，再定衣服。** 把主要人物画在同一地线上，用成片里最小的像素尺寸比较头身、肩宽、躯干长度和站姿。为每人选两项远景仍可见的差异。例如一人短身、肩线平、习惯前倾，另一人躯干长、站直、转身慢。让差异来自具体人物；年龄和性别不能代替造型设计。单主角则对比同一角色在开头与结尾的姿态，保留身份特征。
- **把设定接进渲染。** 在项目使用的角色资产或绘制函数中落实各人的轮廓、比例、常用姿态和持物手。可以共用关节、坐标变换和步态计时；检查最终代码是否只靠换色、饰品或水平翻转生成另一主角。按分镜实际使用的朝向画视图，标明发缝、衣领和惯用手等不对称处。换装或反打时回看同一张设定图。
- **景别决定画哪些细节。** 远景优先保证头肩、躯干和四肢之间的空隙；半身镜补眉眼朝向、肩线和手势；手部或面部特写另画轮廓和遮挡。把同一人相邻的远景与近景摆在一起，检查脸型、外套长度和身体比例能否对上。主要人物在背景最亮、最暗处各看一次，必要时调整人物和背景的明度差。
- **让身体完成剧情动词。** 为当前镜头有意义的动词设计预备、接触和收势姿态。例如递杯时，视线先落到对方，肩肘带动手腕，手握杯柄；对方握稳后，递杯人才松手。逐帧区分杯子在桌上、由谁持有、落桌三个状态。持有期间用同一个手部锚点计算手和杯柄的位置；站定时保持支撑脚落地。转身、角色移动和镜头推近都从同一世界坐标换算。
- **避免断身和穿模。** 从骨盆定位躯干，肩肘腕和髋膝踝逐级相连，头颈随肩线变化。侧身、镜像、缩放和步态共用同一个角色原点。先在透明底检查关节交叠，再放回列车窗、桌沿、被面等前景，检查遮挡顺序。对连续实体造型可检测剪影是否断开；手臂穿胸、错误遮挡或脚底滑动仍要结合姿势和相邻帧目检。
- **验收实际镜头。** 从成片用到的绘制入口抽出最小同框图、同人跨景别对照，以及关键动作接触前后数帧。把姓名、道具和配色遮掉看双人能否区分；恢复道具检查手是否悬空、穿过杯柄、松手后道具是否继续跟手。为每个失败项标明角色、镜头、帧和对应资产，修后在原位置复看。单纯展示角色设定图无法验收成片中的表演。

## 网格、变换与留边

建议从低分辨率世界整数放大，例如 `384×216 → 1920×1080` 五倍，`320×180 → 1920×1080` 六倍。两轴比例一致，缩放关闭平滑；角色、摄像机与遮罩边界落到虚拟像素。

```js
ctx.imageSmoothingEnabled = false;
// starter/frame.mjs 的 FB：摄像机中心使用世界坐标。
const fb = new FB(384, 216);
fb.setCam(192 + panX, 108 + panY, zoom);
// 世界图元走 fb.X()/Y()，rect/line/circle/poly 已统一变换。
fb.rect(-PAD_X, -PAD_Y, 384 + 2 * PAD_X, 216 + 2 * PAD_Y, skyColor);
```

`setCam(x,y,zoom)`、`X(x)`、`Y(y)` 的完整实现见模板。不要把一部分坐标手工平移而另一部分仍画在 `0..W/H`；世界层统一走变换，HUD 和字幕保持屏幕坐标。模板先实际填满有留边的世界，初始透明缓冲可暴露遗漏。

只平移时，横纵留边分别覆盖摄像机最大位移，并多留至少一个像素处理取整。缩小镜头会看见更宽世界：用全部镜头状态计算可见世界边界 `cam.x ± W/(2*zoom)`、`cam.y ± H/(2*zoom)`，让天空、水面、地面与前景覆盖其并集；不要只给天空留边。`PAD=28` 只是特定平移的起点，不能涵盖任意缩放。

在最左/右/上/下及最小 zoom 抽帧，检查四边不出现黑/透明缝。模板有明确 CAMERA_LIMITS；扩大范围时同步扩大世界，不靠背景黑色掩盖遗漏。

| 角色高度 @384×216 | 可读性起点 |
|---|---|
| 10–13 px | 适合远景群像；细小动作可能不可辨 |
| 14–18 px | 主角远景的实用起点；游泳、伸手等需放大检查 |
| 20–32 px | 常用行动镜头，更容易辨认姿态与道具 |
| 40 px 以上 | 特写和表情，需更多轮廓细节 |

数值是美术建议，不是校验器硬门槛；按手机观看尺寸、背景对比和动作复杂度调整。精灵可用 8–12 fps，水纹、镜头与遮罩仍由成片时钟驱动。

## 字幕与图层

世界层在像素网格绘制；常规字幕在输出分辨率单独绘制，避免五倍放大后字形粗糙。模板浏览器用高分辨率 Canvas 字幕层，导出用 FFmpeg ASS；两者的文案与时点都读分镜 JSON，HUD 可按美术选择像素字。字体使用已装、可用的系统字体，跨机器验收字形与换行；新增字体先说明且核对使用范围。浏览器的字体/资产准备、预热及 2D Canvas 验收 profile 见 渲染与恢复。

| 项目 | 1920×1080 的起点 |
|---|---|
| 安全区 | 底部约 25% 作阅读区；距底边 ≥ 92 px、右侧 ≥ 124 px（1080p，以 `safe-area.py` 输出线为准，见 HUD 与字幕） |
| 字号 | 英文约 44 px；中文单语约 40–52 px，双语次行可从 30–40 px 试读 |
| 行距 | 约 1.2–1.35 倍字号；避免遮住人物关键动作 |
| 底板 | 暗板不透明度从 0.4–0.65 试起，亮背景提高对比；横向渐隐可选 |
| 层级 | 世界→道具/人物→氛围→HUD→字幕；转场遮罩仅覆盖所需层，持续歌词不被意外擦掉 |

这些是试读起点，竖屏、字数和字体需另调。逐字填充若用于跟唱，使用 `clamp((t-start)/(end-start),0,1)` 的线性进度，不能给跟唱时间加视觉缓动。没有逐词对齐时注明“视觉填充”；可以只显示整句，不能声称已精准卡拉 OK。模板目前显示整句字幕；按需添加 ASS `\kf` 或独立遮罩时，另记录真实逐词时点或演示均分方法。

在最亮背景与转场中点抽取最终输出帧，按实际播放尺寸试读。白雪、灯光或白场可能吞掉白字；按需要增加暗板、深色描边或阴影，并确认这些层在转场中仍可见。叙事字幕与演唱字幕都要检查，不能只看暗场。

### 系统字体路线（中文）

`pixel-font.py` 只把 `DEFAULT_CHARSET` 里的 ASCII、数字和少量符号烘成点阵，中文没有点阵可用，只能退回系统字体。最小可跑参数：

```python
from PIL import Image, ImageDraw, ImageFont

face = ImageFont.truetype("C:/Windows/Fonts/msyh.ttc", 40)   # 1080p 中文单行起点
mask = face.getmask(text, "1")                                # "1" = 二值掩码，无灰度抗锯齿
glyph = Image.frombytes("L", mask.size, bytes(mask))          # ImagingCore 需转 Image 才能贴
draw.bitmap((x, y), glyph, fill=(236, 244, 255, 255))
```

- 字号：1080p 中文 40–52 px，英文 44 px 起；先 `face.getbbox(text)` 量宽高，再按 22 字上限与安全区排版，别居中完再回头看。
- **关闭平滑**：Pillow 没有关抗锯齿的开关，正解是 `getmask(text, "1")` 取二值掩码（只有 0/255），不要靠在成品图上加滤镜。
- **块面感**靠 `stroke_width`：`draw.text(..., stroke_width=2, stroke_fill=暗色)` 加粗轮廓造硬边；要更方正就 2× 超采样后按阈值二值化、`Image.BOX` 缩回、`Image.NEAREST` 再放大。
- **位置：文字一律画在放大之后的成片分辨率层**（1920×1080），不画在 384×216 世界层。世界层 40 px 的字要占屏宽 1/10，NEAREST 放大后是一团模糊块。这条与本节「常规字幕在输出分辨率单独绘制」是同一条规则，HUD 文字同样适用。
- 字体路径按本机候选列表取（`msyh.ttc` / `simhei.ttf` / `PingFang.ttc` / `NotoSansCJK`），跨机器验收字形与实际命中，新增字体先说明来源与使用范围。

## 按症状排查渲染

以下用于已有工程出现对应症状时排查；内置 Node/FFmpeg 模板不需要 Pillow。使用其他渲染器时先复现最小失败帧，再核对当前版本与画布模式。

| 症状 | 检查与处理 |
|---|---|
| 半透明颜色把画面整片盖住 | 核对图像与绘图的 alpha 模式。Pillow 在 RGB 图上需要混合 RGBA 颜色时可用 `ImageDraw.Draw(img, "RGBA")`；需要独立层混合时用 RGBA 图层与 `Image.alpha_composite`。向 RGBA 图写颜色不等同于已经合成到背景。 |
| Pillow 矩形报 `y1 must be greater than or equal to y0` | 输出该帧的原始和取整坐标，核对上下边顺序。像素世界在绘图边界统一取整；取整后为零宽/高的图元明确跳过或按所需单像素绘制，不把具体浮点/版本现象归为所有 Pillow 的缺陷。 |
| 字幕横笔画缺损或字形断裂 | 用相同字体、字号与最小文本复现，核对字体实际命中、输出层尺寸和最终编码帧。仅当复现了光栅问题时尝试字幕层 2 倍绘制后用 LANCZOS 缩回；世界层仍用 NEAREST。某台机器的字号故障不成为通用字体规则。 |
| 叠化期间人物或地平线出现两份 | 单独查看前后画面、遮罩与转场中点，避免重复叠加多个转场。按叙事选叠化、遮罩或白场；白场是可选表现方式，需另查亮度和字幕可读性。 |

像素光晕可用分层圆形/椭圆与离散明暗保持轮廓；确实需要柔光时在独立氛围层处理并检查像素边缘，避免全世界层模糊把网格一起抹掉。

## 有意义的镜头变化

| 镜头 | 适用任务 |
|---|---|
| 侧视卷轴 | 跑、送、追及增长的距离 |
| 竖向跟随 | 攀升和难以触及的目标 |
| 俯视地图 | 路径、脚印、章节和地理尺度 |
| 室内剖面/特写 | 等待、选择、保留与个人记忆 |
| 圆窗/相册/雪球 | 回忆、梦与被保存的世界 |
| 双人分屏 | 两地共同时钟；跨屏线索兑现联系 |

相册收纳经历、梦窗扩大进入梦、望远镜改变尺度，都可让转场说明关系。双人分屏先建立地点与各自行动，再让光锥、星链或肖像跨屏，连接完成后才共同举灯。可复用遮罩，但结果和文字必须留有阅读时间。

接触表看叙事，关键帧看人物、道具、HUD、边缘与字幕，转场中点专查重复地平线。完整播放看动作与留白；去掉字幕再看一次，确认动作承载含义。

## 场景与道具的美术验收

先选全片回访最多的地点和承担转折的道具，以项目实际绘制入口做一组远、中、近景。按下表定位最需要补画的部分，再扩到其他镜头。

| 检查 | 观察画面 | 优先返修 |
|---|---|---|
| 遮住招牌后还能认出地点吗 | 找出人物工作的区域、可用物和走进去的路径。例如唱片铺的试听台、按类别排列的唱片、柜台后的维修区。 | 先建立平面关系、前后遮挡与可互动地标，再画重复纹理。 |
| 近景比远景多交代了什么 | 远景看谁拿着，中景看怎样交换，特写看手指、受力点和物件的机械反馈。 | 为关键景别单画资产。磁带按键应有按下行程、指示灯变化和随后开始转动的卷轴；把动作与道具所有权放在同一时间线上。 |
| 材质和光源是否属于这个空间 | 比较同一盏灯在塑料带壳、玻璃柜门、纸标签及人物上的反应；轮廓、接触阴影与投影方向要一致。 | 保留大形与明暗组，优先刻画磨损边、玻璃后的陈列深度等可读细节。用材质区别控制像素密度，留出安静区域。 |
| 地点回访有无新发现 | 固定地标后，对照人物位置、天气、营业状态与使用痕迹。让一次互动改变下一镜仍看得见的东西。 | 给原场景追加事件前后状态；重要道具进入特写后要能回到同一个空间位置。 |
| 游戏中的角色是否真的做了事 | 隐去 HUD，能否看出谁接线、谁撑伞、谁跨过断口，以及动作怎样改变局面？ | 让角色先改变可交互物，再更新进度和读数。 |

交付时把代表镜头按目标观看尺寸并排，写明哪一个细节传达地点、哪一个特写新增信息、哪一次反馈证明人物完成了动作。音视频流、字幕、卡点与骨骼检查单独记录。一次聚焦返修可以用几张静帧和关键动作条完成。

## 像素人物的微表情与分层帧率

参考抖音作者 yuyuyu 的《time machine》（作品 7707513346966310198，网页播放器约 03:42）。约 00:31 的画面中，深色发块托住明亮的整块脸，闭眼用折线表现，短平嘴、抱在胸前的手与低对比度夜景共同传递内收的状态。约 02:26 的分屏中，室内角色眼部呈睁开状态，眉毛、眼睛和嘴的像素位置独立可读。两个时点用于比较造型与情绪；网页抽看没有测得源文件帧率、原画更新频率或这两帧间的具体动作过程。

**按歌词设计角色反应。** 为关键一句写「受到的刺激 → 先看向哪里 → 是否掩饰 → 最后身体做什么」。比如听见熟悉的声音：原先视线停在磁带上，眼珠先偏向声源，上眼睑抬起；认出声音后眉心才放松，攥住带盒的手慢半拍松开。这里给出的是新项目的演出例子。其他歌词可以先动嘴、先低头，或让人物完全克制。

**为近景单画一张能表演的脸。** 在项目使用的原生像素网格上先定发际线、下颌、眼线、鼻底和耳位。把左右眉、眼睑、瞳孔和嘴形作为可分别绘制或替换的像素簇。准备本段真正用到的睁眼、半闭和闭眼形状；侧脸与四分之三侧脸分别检查远眼的可见宽度。眨眼时由眼睑遮住瞳孔，嘴角变化时下颌轮廓保持稳定。下眼睑的阴影、面颊色和边缘光只在支持表演时使用。若眉眼口在成片观看尺寸挤成一团，先重构机位、裁切与脸部留白，再补五官。

**在时间线上给表情留出可读过程。** 指定触发处、首次反应、观众能读清的停留和收势；选择一项主变化，其他部位按人物意图跟进。渲染时让表情状态按成片绝对时间或帧索引取值，使跳帧预览和离线导出一致。微表情用手工眼形与口形替换，头部重心、呼吸和环境可以使用较密的更新。眼睛、嘴、肩和背景可共用音乐时钟、各有更新节奏。

**把“像这个参考的帧率”写成可核对的规格。** 有参考文件时用 FFprobe 记录分辨率、帧时间戳与输出帧率，再在固定机位截取眨眼、转头、镜头平移的连续帧，分别标记角色造型保持了几帧、摄影机和环境何时移动。避开弹幕、字幕、水印、压缩噪声和切镜。只有播放器证据时，把目标写成可观察的动作质感，保留帧率待核。项目自选的输出帧率、表情停留时长和动作档位标为本项目参数。

**验收时看同一个人、同一句、同一尺寸。** 从实际渲染入口取「反应前／刚察觉／情绪落定」的脸部裁切，再回到全幅按正常速度播放。隐藏字幕后是否能看出人物看向谁、何时反应、心情如何变？检查眉眼是否互相粘连、瞳孔是否跑出眼白、嘴形是否抖动、头发阴影是否盖住眼睛，以及手势是否和脸表达相同或有意相反的情绪。若意思只靠字幕或换一张情绪图标才能读出，回到眼形、视线和姿态返修。

### 视线、重心与动作收势

先用清晰剪影定下预备、接触、反应、收势，再补中间帧。顺序可以是眼睛先看，头和躯干转过去，手脚到位，围巾和小物最后落稳。交接、落座、转身和表情变化分别取连续帧，跟踪同一只手、同一只脚、同一双眼在各帧的位置。当前镜头有明显运镜时，把同一个世界接触点随镜位投影，再裁原始尺寸细节。开口内对象先裁进屏幕、车窗或门，接着画窗框和遮挡层，最后为真正跨过门沿的身体单独处理前后关系。 [动画排演与裁切参考](https://github.com/Joker-chichi/claude-mv-skill/blob/2ccf0c6ad31f27bb67e4a81e045e912f0a7d3e23/skills/painted-animation/template/ANIMATION_GUIDE.md)

### 为生成背景和片头写场景提示

先用一句能看见的事情表达歌的矛盾，再写给实际绘制工具的完整提示。查同类视觉 skill、图像模型官方提示示例与用户的参考片，记录借用的构图、光照或材质方法，中文另起笔写本曲的空间。可参考 Anthropic 的 [canvas-design](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md) 对空间与材质的描述，以及 OpenAI 的[图像提示指南](https://github.com/openai/openai-cookbook/blob/main/examples/multimodal/image-gen-1.5-prompting_guide.ipynb)对构图、光源及局部迭代的写法。

给生成工具的正文应能直接使用。交代镜位、前中远景的遮挡关系、光从哪里来，木、玻璃、雪或金属怎样接光，人物在哪里动，哪块给歌名留空。描述中的每个意象都要能在画上找到。回访同一地点时写下保留的窗框、座位和光源方向，以及角色这次做了什么。按镜头 ID 保存实际提示、参考、结果静帧和修改记录。走代码绘制时保存同一份美术简报并标注画法。

> 可改写的简报示例。成片画幅与像素网格沿用项目设定。镜头在旧信箱侧前方略低的位置，潮湿铸铁把路灯切成两道断续的铜色高光，左下的石台留有一溜信件拖过的水迹。中景的送信人手抬到投递口，信角先被窄槽遮掉，手收回来时门内落下一小束暖光。远处只有社区入口两盏冷灯。第一次到这里，右边夹着待取的蓝签。回访保持灯柱和信箱同位，蓝签被取走，主角转身时把留在画外的路让出来。前奏若用这一场，右上留深色搪瓷牌供后期放准确歌名。

前奏先设计第一帧和进第一个故事镜头的动作。歌名可成为橱窗烫字、票面或游戏菜单，选与歌曲地点有关的载体，让前奏里有事发生。标题和字幕在交付分辨率单独排字，查看实际编码后的一帧。参考片有原文件时测量帧率；转场记录触发、时长、遮挡方向和下一镜承接的物体，再逐帧检查。声音提示记录听见的音色、瞬态、尾音、空间方向与画面落点；可用同版本原声校对新增声音。生成方法只在有作者说明时归因。

同地点回访时，给每次出现写下观众新知道的事，落实到一个能被看到的区别。可以让第一次的物件在第二次被划掉、合起、装进相册，或通过人物缺席和光源转移改变同一构图。比较镜头时区分地点复用、机位复用和实际画面复用。复用一段提示音也可让跨场景的同类情感事件互相呼应；先用原曲对齐检查候选，再结合触发前后的画面解释用途。

### 从认可的样片续成整曲

保留用户认得的造型与表演。把已认可的远景小人、左右朝向的近景头像和道具内的小照片接到同一组角色资产。以《四格相纸》为例，短圆脸、大面积脸颊、短眼形、两簇腮红构成同一画风；短发和侧发髻的剪影能区分人物。换角度后，视线仍朝向手要碰的地方。其他风格沿用各自获认可的特征。

为动作写出意图和后果。擦泪时先看见眼泪，手从自己的肩膀伸出，方巾碰眼角后眼睛才闭上，手放下后泪珠消失。验收取动作前、接触、反应、收手四个状态；在最后导出的正常观看尺寸上检查。让道具留下结果，下一镜才能接着讲。全曲延展时，让旧道具有新的用途：第一次照片记录两个人，第二次照片留下一个空位，尾声人物决定如何安放旧照。道具、职业和地点随歌曲另选。

## 像素 RPG 文字制作案例

本文是从歌曲分析到成片验收的文字流程示例，不附带视频或画面素材。它把参考视频中可观察的像素 RPG 组织方式转成可复用制作步骤，不复用其角色、歌词、对白或具体素材。参考片的证据范围与时点见 参考片取证记录。

### 项目假设

用户给出一首歌、经校对的歌词、横屏交付规格，并要求复古像素 RPG 的菜单、地图、头像对白和情绪状态界面。歌曲实际内容尚未指定，因此下面只用阶段名和歌词 ID，镜头起止须从本项目音频与歌词账本生成，不能复制参考片时点。

示例故事方向是“主角想把一份迟来的邀请交给旧友，沿途几次犹豫，最后决定当面送出”。这是可替换的创作假设，不是歌曲事实。若真实歌词不支持邀请、旧友或送达动作，应依实际歌词重写。

### 1. 先锁定歌曲证据

1. 记录文件哈希、录音版本、源起止、成片时长、画幅、帧率与音轨授权。
2. 按听辨或可信对齐核对每句歌词的成片起止、重复关系、拖音与停顿；LRC 行时点不能充当逐词时点。
3. 标记主歌、副歌、间奏、转折和情绪峰值。BPM、拍点和句起候选写明来源与置信范围，关键动作在实际音轨中试听确认。
4. 把事实、推断和虚构演绎分开。无法查证的创作背景留空，不替歌词补造真人经历。

### 2. 把美术系统与故事状态分开设计

#### 美术系统

- 先定内部网格、输出尺寸、硬边放大倍率、轮廓像素尺度和全片色板。
- 角色卡固定头发、服装外轮廓、身高比例、常用姿态、朝向和持物锚点。两位主角做同尺度纯黑剪影对照，去色后仍能辨认。
- 地图层用远景、树列/建筑、地表、前景遮挡组织纵深。菜单、木框对话面板、头像格和章节牌使用统一边框、角饰、色阶与字形规则。
- 对话框位置和人物朝向相互对应，保留说话角色头像、文本留白及画面动作区；界面不能遮住关键接触、道具或表情。
- 天气、昼夜和地点变化沿用相同像素密度、角色比例、材质颗粒与光源逻辑。切场景不是重置角色或 UI 状态的理由。

#### 故事状态

| 状态键 | 初始值 | 触发行动 | 可见反馈 | 后续承接 |
|---|---|---|---|---|
| `invite` | `draft` | 主角在地图终点打开邀请界面 | 草稿图标变为已发送信封 | 下个地点保留“已发送”，不自动变成已读 |
| `reply` | `unknown` | 歌词对应的等待段结束，收到实际设定支持的回应 | 对话框出现新头像和回应状态 | 之后的关系页仍显示该状态 |
| `weather` | `clear` | 转折段进入夜间场景 | 背景换为雨夜，地面反射随雨线变化 | 相同街道回访时保留夜雨 |
| `meeting` | `not-met` | 结尾段发生当面动作 | 地图标记和任务记录更新 | 片尾保留真实结果，不用数值替代结局 |

数值或图标必须能追溯至歌词和人物行动。若无法解释一个心形、计数器或状态条为何变化，就删除它或改成明确的行动反馈。

### 3. 按歌曲段落搭建分镜账本

每句歌词先有独立 `lyricId`，再映射到镜头内的主体、景别、行动和结果。以下是结构样例，标题用于理解段落功能；实际歌词、时间和事件依项目填写。

| 阶段 | 画面与游戏界面 | 歌词/音乐关系 | 状态与跨镜连续性 |
|---|---|---|---|
| 开场 | 天空、山线和树列形成标题地图；菜单项逐个出现，选择反馈后进入地图 | 标题停留服从前奏长度；菜单确认声或高光只有在可听落点核实后才卡点 | `chapter` 从 `title` 变为 `map`，保留玩家位置 |
| 主歌 A | 俯视路线展示主角目的地，地图标记随行动推进；近景看清主角手中邀请 | 每个歌词 ID 对应路线、目标或动作，不让地图移动掩盖人物行为 | `invite=draft`，目标地点进入任务栏 |
| 副歌 A | 暖色木框对话和固定头像承载一次沟通；镜头交代对方所在空间 | 行动峰值对准经试听确认的音乐重音，完整歌词仍按校对时点显示 | `invite=sent`，`reply=unknown`，不可提前把等待画成答应 |
| 主歌 B | 回到先前街道，但切为夜雨；雨滴、窗灯和脚步改变同一地点的情绪 | 重复句使用新动作或新信息，不能只换字幕颜色 | 天气与已发送状态连续，人物服饰、道具位置不跳变 |
| 转折/间奏 | 打开关系或日志面板，展示前面行为留下的记录；随后回到场景完成一次选择 | 器乐可继续推进地图、计时或动作准备，避免停成无因果的展示页 | 仅更新由明确事件触发的字段，记录状态变化时点 |
| 结尾段 | 进入有水面或远景留白的原创地点；人物完成歌词所支持的动作，用章节牌或像素遮罩结束 | 让最后一句与动作结果有足够停留，不强加未经核对的歌词卡点 | `meeting` 按真实剧情结算，最后一帧保留结局状态 |

#### 单镜账本字段

```text
sceneId: verse-b-street
clipStart / clipEnd: 从已核对时间线填写
lyricIds: l012, l013
shot: 中景转头像对话近景
actors / costume / props: 固定 ID 和当前状态
objective: 主角希望得到一次明确回应
action: 停步，打开对话界面，发出邀请
feedback: 状态从草稿变成已发送，对方暂未回应
outcome: 主角收起设备继续前行
hudBefore / hudEvent / hudAfter: invite=draft → send → invite=sent
musicAnchor: 候选时点、证据来源与待试听状态
exit: 让下一镜继承位置、动作方向、雨势和 UI 状态
```

### 4. 先做静态资产和动作验证

1. 按场景顺序完成角色卡、黑色剪影表、地图草图、UI 组件表和关键帧接触表。
2. 给关键动作做 4–8 帧姿态条，核对脚步、手部、道具接触、说话朝向和动作结束姿态。
3. 先看无字幕静帧，再看字幕版；在实际成片尺寸检查字形、对比度、头像一致性、遮挡和安全区。
4. 用户要求视频样片或确有动态风险时，再选一段能覆盖动作因果、状态变化、转场和字幕阅读的范围渲染。用户跳过时不生成 MP4，用静帧、姿态条、分镜校验和状态账本继续。
5. 沿用用户已有项目的正常入口。新建代码项目时将 `assets/templates/starter/` 仅作为确定性帧与导出功能检查模板，先替换其技术检查画面和默认文案，再写本项目场景。不要把模板默认画面、颜色或剧情当作美术方向。

各阶段以场景及人物静帧定版为生成前确认步骤，先提交该范围的全部场景、每位主要人物远近景和关键动作图。用户可选择跳过动态试片。

### 5. 扩展与验收

- 先把完整目标时段的歌词、镜头、事件和章节覆盖好，再实现逐帧画法；每个重复段落都交代新增信息或后果。
- 浏览器预览和导出使用相同时间函数、角色资源、词级时点和转场定义。固定随机种子，按时间直接求值，验证重复、逆序和跳播帧一致。
- 若选用词级高亮，`words[]` 按顺序拼接须与可见歌词完全相同，时点来自实际音频校对或可信对齐；没有可靠词界时用整句字幕。
- 用分镜校验器检查时长覆盖、状态字段、事件因果、角色/道具引用与时间基准。以接触表检查段落变化，以完整解码、抽帧和试听检查动态交付。
- 记录实际核查的音画范围和待确认项。1 fps 抽帧、自动转录、BPM 候选或静帧都不能单独证明精确同步或动态连续性。
- 用户只要 skill、制作方案或分镜时，交付这几项和未验证边界，不渲染视频、不把技术模板输出当作成片样片。

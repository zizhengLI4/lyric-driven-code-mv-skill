# 时间与分镜

## 一套成片坐标

源音频从 `sourceOffset` 秒截取；歌词、节拍和事件统一成片秒：

```js
const t = frame / fps;
const sourceTime = sourceOffset + t;
const clipTime = annotatedSourceTime - sourceOffset;
```

只在数据入口换算一次。源片段 `[37.2,49.2)` 中句子 `[38,41)` 转为 `[0.8,3.8)`；重复出现的句子分配新 ID。已经剪好的音频记录 `audio.timebase="clip"` 并从零播放；源文件用 `"source"` 并裁掉 `sourceOffset`，避免重复偏移。分析脚本输出已是 clip 秒，不能再减偏移。

所有区间用 `[start,end)`。截断跨片段边界的歌词及事件，保留必要前置状态。让 `duration=durationFrames/fps`；最后一帧时间为 `(durationFrames-1)/fps`。嵌套场景的 `local=t-scene.start`，Remotion Sequence 内的帧已是局部帧，不能再减场景起点。

## 渲染函数收到什么时间

**在每个渲染入口写明时间含义，并在适配边界转换一次。** 分镜保留成片秒；场景画法可以使用成片秒或镜头局部秒，关键是动作参数与函数入参使用同一坐标。

| 入口或数据 | 时间含义 |
|---|---|
| `renderFrame(clipT)`、JSON 的句起止、`event.at` | 从成片第 0 秒起算 |
| `renderTimelineFrame` 的 `drawScene(index, localT, options)` | `localT=clipT-scene.start`，当前镜从 0 起算 |
| 原曲注释与音轨截取 | `sourceT=sourceOffset+clipT`，仅在音频入口换算 |

例如镜头 `[16.8,46.2)`：成片第 30 秒是 `localT=13.2`；JSON 事件 `at=33` 转为该镜动作点 `eventLocal=16.2`。按成片秒写的 `ramp(t,33,34.4)` 不能直接接收 `localT`。沿用这种旧画法时，可在 `drawScene` 的适配边界恢复成片秒：

```js
const drawScene = (index, localT, options) => {
  const scene = options.timeline.scenes[index];
  return drawUsingClipTime(scene.start + localT, scene, options);
};
```

下一镜预卷的 `localT=0` 恢复为**下一镜的 `scene.start`**，不是转场当下的成片时间。反过来，纯局部画法把 JSON 事件转换为 `event.at-scene.start`，之后不再减镜头起点。

starter 还包含一层演出缩放：JSON 路线在调用 `SCENE_RENDERERS[scene.id]` 前使用 `designT=localT*6/(scene.end-scene.start)`，使内置 `send/receive` 的 6 秒演出适配实际镜长。当前注册画法收到的是这套设计秒；新增画法应声明并适配这个约定。需要直接使用真实 `localT` 的工程可在 `renderTimelineFrame` 的 `drawScene` 层接入自己的画法。不要把设计秒误当成片秒或真实镜头秒。

## 从含义到事件

先写一句“人物想要什么，因什么受阻或改变”，再设计可见演出。

| 含义 | 目标与行动 | 反馈与结果 |
|---|---|---|
| 珍惜纪念物 | 抱起礼物，选择保留，摆上搁板 | 完整礼物留下，保留标记出现 |
| 遇到阻碍 | 尝试推进目标，发现路径受限并选择新行动 | 路线状态更新，画面呈现新的限制或可行选项 |
| 付出与消耗 | 攀升、奔跑、跨过风雪 | 距离增大，体力改变；变化对应动作 |
| 回忆变冷 | 触摸照片，结冰，再尝试解冻 | 图标失色、裂纹、温度格变化 |
| 建立联系 | 选择沟通方式，等待对方或系统回应 | 对话状态与关系反馈随实际回应更新 |

让动作准备稍早开始，峰值对准需要强调的音乐点。缓慢观察、句尾停留和间奏可以继续推进地点、记忆与关系。重复副歌可以先呈现一次未果的行动，再揭示新的信息或后果，增加故事层次；副歌不必全部变成成功。

## 器乐与原创叙事字幕

纯器乐可以配原创叙事字幕。继续用 `lyrics[]` 保存句子、起止与镜头引用，在项目说明或 `note` 里写明“原创叙事字幕，音轨无人声演唱”及文案作者；这不增加必填 schema 字段。文字由故事设计，不称为歌曲中已演唱的歌词。允许整句显示并按阅读需要留时，也可在动作前预示或动作后回应，不套用演唱逐词跟唱规则。

先识别能说明段落变化的音乐结构、音色或和声变化，再为需要强调的动作选择落点；能量拐点与拍点都是候选证据。切镜可以随乐句、留白或叙事结果发生，只对明确声明 `sync:"beat"` 的事件检查踩拍，不要求每镜事件、HUD 负反馈或每个切点都在强拍上。

器乐不自动限定为 `draft`：只有机器分析或尚未试听时保持 `draft`，方法、限制与 `pendingChecks` 写明待确认的乐句边界、节拍相位或动作峰值；人工听辨并核对相关片段后，可以按实际范围记录 `verified`。核对对象是配乐结构、动作与叙事字幕的阅读时序，无人声时不宣称逐词演唱对齐。自编时点的演示仍用 `illustrative`。

## JSON 约定

`schemaVersion:1` 保持兼容，可增加工程特有字段。

| 字段 | 内容 |
|---|---|
| `schemaVersion`, `timebase` | `1`、`"clip"` |
| `project` | `fps,duration,sourceOffset,width,height,virtualWidth,virtualHeight,seed,settings?,audio,sfx?` |
| `project.settings` | `{beatToleranceMs?}`；默认 80 ms，须为非负有限数，分镜 CLI 会将其传给节拍校验器 |
| `project.audio` | `path,timebase,provenance?,license,credit,url?,licenseUrl?,use`，授权说明见音频参考 |
| `device?` | `{id,type,name,purpose}`；先描述承载叙事的界面、系统、时间轴、视角或材质舞台，再决定场景画法 |
| `chapters?` | 至少一个且连续覆盖 `[0,duration)` 的 `{id,start,end,title,meaning}`；用于标题牌、章节牌或关系阶段，不替代 `scenes[]` |
| `captionStyle?` | `{mode:"bottom"|"scene-panel",placement:"bottom"|"integrated",lines:1|2,primary,secondary,panel,chapter}`；`scene-panel` 将歌词做成画面内像素 UI，预览与 ASS 导出共用归一化配置 |
| `lyrics[]` | `id,start,end,text`，可加 `zh,en,words[]`；有意跨镜可加 `allowSceneSplit:true,splitReason` |
| `music` | `status,beats[],sections[]:{id,start,end},evidence?,presentationNotice?,pendingChecks?` |
| `music.evidence` | `method,limitations,reviewer?,reviewedAt?`；最后两项用于人工核对 |
| `music.pendingChecks[]` | `{start,end,check}`：成片秒区间与具体未确认内容；草稿交付时必需非空 |
| `actors[]`、`props[]` | 稳定人物 ID 与 `costumes[]`；道具 ID 列表 |
| `scenes[]` | `id,start,end,meaning,location,objective,action,feedback,outcome,lyricIds,actors,props,events,exit,materialVariant?,hud?` |
| `scene.materialVariant` | `{id,label,change}`；同构图换季节、材质或年代时记录可见变化，画法仍需自行实现 |
| `scene.hud[]` | `{id,type,label,value?,min?,max?,meaning}`；`value` 若提供为非空字符串或有限数，`bar` 要求数值落在 `min..max` 内；类型可为 `counter/bar/heart/status/clock/badge/log/checklist/axis/level/score/banner`，负值、归零、损坏和失败均可作为语义结果 |
| `scene.actors[]` | `{id,costume}` 引用根人物表 |
| `scene.events[]` | `{at,action,hud?,sync?,lyricIds?,meaning?,support?}`；`at` 为成片秒，位于镜头内且升序 |
| `project.sfx[]`, `scene.sfx[]` | `{at,type,gain?,pitch?,hitAt?,anchor?}`；`at` 是波形起点；`anchor` 可为 `visual/beat/free`，visual/beat 锚点须写 `hitAt`；visual 仅在镜头内绑定事件 |
| `scene.exit` | `{type,dur,origin?,target?}`；类型为 cut/dissolve/ripple/water |

主场景连续覆盖 `[0,duration)`，不重叠、不留洞。角色装束明确指定；道具拥有、消耗与保留另记状态并核对。`scene.lyricIds` 引用与镜头相交的歌词；留白镜头可为空。

`lyrics[].words[]` 是可选的逐词显示数据，不改变 LRC 的整句导入或旧稿。每项为 `{text,start,end}`，时间使用当前项目的成片绝对秒。每个 `text` 是可见主行 `zh ?? text` 的连续片段，按顺序拼接必须完全相同；空格可附在相邻词片段上。词的区间须位于所属歌词内、按序排列且不重叠，可保留词间空隙。预览与 ASS 导出共用这些词界，当前、已唱和未唱片段分别使用强调色、主色和辅助色；ASS 以百分秒为精度，量化后为零长的词会被拒绝。词界应根据实际音频核对，均分时长只可作为视觉演示，不能称作已同步。

先选 `device` 再选场景：装置决定观众如何读懂状态，场景只负责这一段目标、行动、反馈和结果。`chapters` 可以让标题牌、关系卡或结算牌拥有明确时间区间。长镜头没有固定秒数上限；镜长由信息密度决定，建议每 8–12 秒至少有一次可读变化（字幕、HUD、光线、材质、粒子或状态），留白可以保留。

starter 的 `--storyboard` 直接读取项目配置、歌词、场景、章节牌、`captionStyle` 与 `exit`，绘图函数通过 `SCENE_RENDERERS[scene.id]` 注册。自带 `send/receive` 画法按镜头局部时长求值；新增 ID 需实现对应画法，JSON 只定义分镜而不生成世界层美术。`device`、`materialVariant` 和 `scene.hud` 是语义元数据，校验器会检查结构；`captionStyle` 与 `chapters` 则由 starter 的歌词层直接绘制。字幕文案仍只从当前 JSON 的 `text/zh/en` 读取；源音频路径与配置覆盖规则见 starter 说明。

`exitTransition` 自由文本仍接受，用于旧工程的叙事说明；新工程采用结构化 `exit` 确定时序。`cut` 的 `dur` 为 0，其他转场满足 `0 < dur < end-start`。`origin` 是两个 `[0,1]` 归一化坐标。`target` 默认为下一镜，也可明确写下一镜 ID；末镜非 cut 必须 `target:"background"`。

starter 当前实现通用分镜规范的执行子集：末镜仅支持 `exit:{type:"cut",dur:0}`。末镜 `target:"background"` 转场需由现有框架或自定义渲染适配实现；通用分镜校验与 starter 执行校验分别检查规范有效性和模板支持范围。

## 出口转场与预卷

```json
{ "exit": { "type": "water", "dur": 0.9, "origin": [0.55, 0.62] } }
```

前镜 `[0,6)` 时，转场窗口为 `[5.1,6)`。窗口中前镜继续按当前 `local=t-start` 求值，下一镜固定 `local=0` 预卷，再按遮罩合成。到 `t=6` 切入下一镜并从零正常播放。末镜淡至背景时只揭示项目定义的背景，不虚构下一镜。

转场占前镜尾段，不另加镜头时长，也不延长总片长。将结果动作安排在转场之前或确保遮罩期间仍可读。水面/地平线等跨镜元素通过相同世界坐标或明确遮罩对齐，重点查看转场中点与边界，避免双地平线。

## 语义提示的边界

- 句子被镜头边界切开会提示；有意拆镜时写 `allowSceneSplit:true` 与具体 `splitReason`，字幕层保持连续。不能由提示直接推断叙事一定错误。
- `event.sync:"beat"` 对照最近 `beats[]`；`scene.sfx[].anchor:"beat"` 以 `hitAt` 对照同一节拍网格，波形起点 `at` 可提前。默认容差 80 ms，可由 `project.settings.beatToleranceMs` 调整；`visual` 锚点须对应同镜头、同一时点的 `scene.events[]`。歌词起句或缓慢动作不必都踩拍，节拍表为空时提示证据不足。
- HUD 可由事件/镜头的 `lyricIds` 支撑，间奏可由 `event.meaning` 或 `support` 解释因果。`event.lyricIds` 必须与本镜相交，并由 `scene.lyricIds` 支持或在事件 `at` 时有效；预示动作可添加镜头级引用。引用可定位不等于含义已经正确。
- 普通模式返回提示；`--strict` 将全部警告升为失败。这是结构检查的退出码策略，草稿可以通过，状态仍为 `draft`。`--delivery` 检查许可记录与音乐证据，`audio.use` 为 publish/public/commercial 时也启用同样检查；两者通过均不证明许可有效或实际音画已经核对。

音乐状态遵循 SKILL.md 三档规则。`draft` 可以有空 beats；交付检查要求方法、限制与非空 `music.pendingChecks`。每项满足 `0 <= start < end <= duration`，`check` 写明尚未确认的句起止、节拍相位或动作落点；仅“待核对”或 `pending` 等占位文本会失败。例如：

```json
"pendingChecks": [
  { "start": 6.3, "end": 8.5, "check": "确认重复句尾音与伸手动作峰值的对应关系；目前只有机器时点" }
]
```

清单在普通模式可省略，保持旧分镜兼容；提供时仍校验字段和区间。校验器能确认可定位的记录，具体描述是否完整需在核听时判断。`verified` 必须有人工核对记录。均分逐字点亮属于视觉填充；离线起音检测不是歌词识别或对齐。

## 确定性求值

```js
const local = t - shot.start;
const progress = Math.max(0, Math.min(1, (t - actionStart) / actionDuration));
const sprite = Math.floor(Math.max(0, local) * spriteFps) % frames.length;
const x = Math.round(x0 + (x1 - x0) * progress);
const state = events.filter(e => e.at <= t).reduce(applyEvent, initialState());
```

位置、镜头、数值、粒子和遮罩都由时间求值，随机初值固定种子；物理可预模拟保存轨迹。`renderFrame(t,options)` 返回 `{width,height,data}`，data 为 RGBA 字节数组；同一时间与 options 应给出相同像素。资源先准备好，不能使用运行中的页面时钟或上一帧累积状态。

```sh
node scripts/qa.mjs path/to/frame.mjs --duration 12 --fps 30 --storyboard path/to/storyboard.json --out work/qa.json
```

脚本自动覆盖首尾、每镜首/中/尾、转场前/中/后及事件周围，用正序、重复、逆序和固定乱序比较 SHA-256。`--times 0,5.1,5.55,6` 可专查落点。其他框架提供一个导出相同 RGBA 契约的适配模块；浏览器 profile、资源准备及预热见 渲染与恢复。报告只检查所抽样时间在当前环境的确定性。

## 分阶段制作

适用：从 MP3 与歌词开始制作、需要逐轮交给编码 AI 的提示词、学习像素 MV 教程，或修改角色与字幕。已有工程从当前阶段继续，复用已确认素材与授权。

需要解决已有 MV 的高潮、构图、角色、清晰度或转场问题时，读 进阶评审与定向优化。其评分表和专项提示词接在 C 阶段样片与 D 阶段扩展之间，也可直接用于成片的局部修正。

### 四阶段协作链

用户未指定风格且适合像素叙事时，可参考《四格相纸》实帧与制作基准。选用生活 RPG 界面时，读《普通朋友》00:00–01:06 开场成片的地图、木框字幕与状态反馈。

按拆歌与研究、故事分镜、实际静帧自检和用户确认推进。样片按需做，扩成片前确认新增场景和人物。

三条视频的本地时长、完整时间线抽样和证据范围见 参考片取证记录。将《普通朋友》作为风格参考时，按其完整成片开场设计连贯的标题界面、地图探索、人物交流、天气/明暗变化和收束镜头；教程段只用于理解制作演示，不能替代成片视觉目标。教程型视频中的讲解依据 ASR 草稿辅助定位，歌词与节拍仍须按实际证据标注。

### 新增教程的制作框架与视觉方向

用户后来提供的两段教程补充了「先听/测音乐、再规划画面、最后分段实现和检查」的实操顺序。教程以一个编码 Agent 与本地音轨为例，说明代码可以逐帧生成动画并按音乐剪接；这是制作路径示例，不把某个模型、平台或固定 BPM 变成依赖。教程里的讲解卡片、软件窗口、绿/黄高亮是知识视频包装；它们不等于音乐 MV 的画风。

按当前工程复用以下顺序：

1. **建项目文件夹。** 放入歌曲、用户提供或校对的 LRC 歌词、风格参考、BRIEF 和输出资料。LRC 已有时先解析；没有时可用本地音频转录生成草稿，标记 ASR 待校对。不能用自动识别稿覆盖用户歌词。
2. **写需求卡。** 记录主题、观众、结尾希望留下的感受、画幅、目标时长和字幕方式。需求不完整时按歌曲提出默认并记为创作假设。
3. **制作歌曲地图和听感笔记。** 查看实际音乐文件，给出歌词句段、停顿、乐段、强弱变化和卡点候选。另写开头情绪、段落转折、最高能量处、编曲质感和收尾余味，使用日常语言即可。BPM、拍号和每小节重拍必须分别有证据；若听感、局部窗口或半速/双速候选冲突，标待复核，不把理论网格当成已听准。
4. **先构思故事和画风。** 用歌词事件安排旅程。风格未定时，为同一段内容出三张代表静帧/风格方向图，让构图、角色、配色与情绪差异一眼可见，再选一套贯穿全片的规则；用户已确定像素风时保留该方向，只比较像素尺度、构图和光色。使用代码动画、现有素材或用户已选工具，逐镜沿用角色资产与场景状态。
5. **把歌词转成单镜头事件。** 具体、可画的词按字面找主体和动作；抽象句用色彩、天气、表情、姿态、景别或留白表达。每镜只设一个主视觉事件，写清准备、动作、反馈和结果。根据听感与实际能量安排强弱，歌曲最高点承担全片最大的构图或动作，不固定为某一种特效。
6. **再按段落实现。** 先完成一段典型主歌或副歌，把镜头 ID、歌词区间、动作开始/峰值/结果、切点及拍点建议写入同一分镜。首批验收后再铺开全曲；局部问题只改对应段落。样片是可选项，不需要样片时用静帧接触表和动作条继续。
7. **最终自检。** 每秒接触表用于找字幕遮挡、主体越界和明显跳变；动作连续性、转场流畅度和卡点必须对问题区逐帧或播放核查。检查故事是否前后连贯、角色与服装是否一致、字幕是否可读、转场前后动作是否连续、音轨与成片时长是否吻合。记录修正与仍待人工试听的时间，不把波形图、BPM 数字或抽帧检查写成“卡点已验证”。

教程中 2–6 秒是作者给的镜头长度参考；用于本项目时只作为节奏起点，依歌词密度、动作和情绪调整。长句、停顿和关系变化可以留长镜头；鼓点密集段可缩短镜头。要求踩拍的事件才吸附高置信候选，其他切点允许落在乐句、动作准备或情绪结果上。歌词是否具象、抽象要先在歌曲地图中标记，避免所有句子都变成同一种字幕替换。

画面审美可借鉴教程样片中连续展开的像素小镇/城市、屋顶到水边的场景旅程、小比例可辨角色、昼夜/天气/光线递进和歌曲最高能量处的强事件。地图变化、对话、标题、任务或状态 UI 都要服务同一段人物行动；具体角色、故事、标题、色板和高潮事件按歌曲重新设计，不套用参考片的猫、人物、台词或烟花。具体歌词用物件/动作具象呈现，抽象句用颜色、天气、表情、姿态和景别转译；每镜聚焦一件事，低能量段保留安静，高点再扩大画面力度。

### 先把范围和路线落到文件

用现有歌曲文件和工程检查真实时长、已装工具与交付目标。将以下内容写入工程的 `BRIEF.md`；无法核对的字段标为待核对，而不是补一个看似精确的数字。

- 音频路径、版本、实测时长，源截取起止及成片范围：片段或整曲。
- 校对歌词来源、时间校对状态、是否需要歌词字幕。
- 简短听感笔记：开头感觉、情绪转折、最高能量处、编曲变化和结尾余味；未试听的部分明确待核对。
- 画幅、成片帧率、内部网格、放大倍数、字幕层策略。
- 角色 ID、核心意象、故事结局、现有素材与工程。
- 当前阶段、已确认版本、实现路线、待补依赖、验收与交付范围。

画面代码与视频渲染是两个环节：沿用已有框架；普通像素演出可用原生 HTML/Canvas/SVG 配合已具备的逐帧捕获链路，已有 HyperFrames 或 Remotion 工程则沿用其正式渲染入口。读 依赖与交付，使用 HTML 视频框架时先读 `hyperframes`，React 视频先读 `remotion-best-practices`。仅学习教程或写分镜时无需初始化视频框架。

### AI 协作与确定性渲染分账

视频页面声明内容由 AI 生成时，不能据此推断作者的完整工具链。页面标题、自动章节摘要或单张模型对话截图只能支持它们直接显示的信息。

若当前项目实际使用 AI 辅助，且需要复现制作过程或说明生成素材来源，可在 `BRIEF.md` 或交付清单记录 `aiAssist`（模型与版本，若可确认；参与的任务；提示词或结果的保存位置；人工修改范围）。若使用 AI 生成素材，再记录 `generatedAssets` 的来源和人工修改。渲染器、后期工具与人工复核只写实际用过或检查过的项目，不适用的字段可省略。

最终帧、时间线、歌词时点、固定随机种子、资源 ID、字幕排版和导出参数由实际采用的渲染与后期流程负责。明确区分 AI 草稿、生成素材与最终成片，不能从“AI 制作”推断为全自动生成、自动对拍或自动渲染。未知信息写作 `unknown`，不猜测模型或服务。

记录格式示例，按项目实际使用填写：

```yaml
aiAssist:
  model: unknown
  tasks: [lyric-mapping, style-draft, transition-ideas, word-cue-draft]
  promptLog: work/prompts/
generatedAssets:
  source: work/generated-assets/
  humanEdits: work/asset-notes.md
renderer:
  engine: starter
  deterministic: true
postProcess:
  tools: [ffmpeg]
humanReview:
  audio: unheard
  visual: sampled
```

录屏可用于快速预览；用户明确要求录屏交付时检查掉帧、光标、浏览器控件与音频来源。默认成片采用可重复的逐帧渲染。新包、浏览器、模型下载或外部 API/付费服务在使用前说明；缺少生成服务时可继续分镜和代码绘制，不把订阅或 Key 设成全流程前提。

### A：歌曲分析与叙事选择

用户只给了歌曲时，这一轮之前先做 从一首歌到连续分镜 的联网考据：查作品身份、创作意图、外部世界、接受史，把来源与 `fact`/`inference`/`creative` 三档判断写进 `research.md` 与分镜 `research` 块。用户已给人物或剧情时，跳过考据里"设计人物/故事"的部分，只用来源补世界细节，不动已给设定。

```text
读取（音频路径）与（校对歌词路径），目标范围为（源起止/整曲）、（画幅）。先核对实际音频时长和版本，完成分析，暂不生成画面代码。

输出歌曲段落与重要音乐变化，以及逐句歌词表：句 ID、起止、原文、是否重复、校对状态。重复句分别保留，考虑拖音、停顿与留白。读取或试听能力不足时说明限制，将时点标为待核对；BPM、重音和精确秒数只报告实际能核对的内容。

能联网时补一节创作考据：作品身份（词曲/发行/版本）、创作意图（访谈、创作手记、专辑文案）、歌词里的人名地名方言器物。每条 claim 标 fact（来源直说）/ inference（你的推断）/ creative（你的设计），fact 与 inference 必须指回来源；查不到的写进 gaps，不要用"据悉""据说"填空。把结果写成 research 块。

提出两种叙事方向，说明人物关系、欲望、阻碍、结局与核心意象。区分歌词事实和创作解释，为重要段落写目标→行动→反馈→结果；不是所有情绪都需要变成数值。歌词字幕默认整句出现，游戏对话可另用打字机效果。

保存 BRIEF.md、research.md、歌词时间数据和分析结论。列出下一阶段可用的方案、未知项与已有成果；本轮止于分析和选择。
```

完成判据：目标时长来自真实音频；歌词不漏句、重复不合并；待核对内容可定位；人物/事件能依据歌曲解释；`research` 里标为 fact 的每一条都能指回来源，编造的背景已被降级为 inference 或 creative。只有短音频时按片段完成，缺少原曲时不声称制作完整原曲。

### B：静帧美术、角色与事件分镜

```text
依据已选方案和歌词时间表，设计像素 RPG 演出。先完成主要角色设定卡、黑色剪影对照表、两张不同叙事段落的代表静帧，以及原尺寸角色动作条，不进入整曲动画。

固定角色 ID、叙事功能、轮廓、发型/装束特征、身形比例、站立尺寸、朝向、常用姿态和道具持握点；每人列出至少两个不依赖颜色的小尺寸识别特征。先把全员剪成纯黑并排：遮住名字、色彩和小道具后仍应能区分；恢复颜色并缩到成片群像里最小的实际尺寸再核对。人物维持小比例角色，特写使用单独绘制的相应素材，不把身体放大代替动作设计，不用重滤镜或额外噪点替代造型。

明确内部网格与成片尺寸的同轴整数放大关系。例如 480×270 放大四倍到 1920×1080；竖屏可用 270×480 放大四倍到 1080×1920。世界层关闭插值并对齐网格，中文字幕独立清晰绘制或使用经过可读性检查的字形图集。

分镜表记录：稳定镜头 ID、源/成片起止、歌词 ID、场景、人物行动、事件结果、可见反馈、所需素材与音乐落点校对状态。完成任务会改变人物或世界；重复段落发展事件。保留背景空间层次与留白，HUD 只显示当前有意义的信息，歌词和任务文字分区。

保存角色设定卡、剪影表、动作条、场景配置、分镜数据和所有场景静帧。每位主角单独保存全身远景和原生面部近景。两张代表静帧用于早期方向比较。提供原尺寸、最小群像尺寸和成片尺寸预览，指出仍容易混淆的角色对、美术或文字问题；剪影盲测与群像辨识度未通过时先重画失败角色，本轮止于静帧和分镜。
```

完成判据：两张静帧能代表不同段落；主要角色的无色剪影能区分，配色不是唯一身份线索；最小群像尺寸下仍能认出每人至少两个稳定特征，单人近景与群像的身份一致；动作条表现方向、姿态和持物关系；亮暗背景字幕可读、像素尺度一致。字数和字幕高度随实际歌词调整，不把教程画面比例设成所有项目的固定要求。

### C：事件闭环与代表样片（可选）

```text
复用已确认的风格表、静帧美术、角色、歌词和分镜，实现当前工程的像素演出。
先完成一个事件触发→人物行动→结果可见的短动作闭环。取得本项目静帧确认后，用户要求样片或动作、转场、歌词字幕需要动态验证时，制作（样片范围）；未指定时用约 10–15 秒，覆盖角色动作、一句歌词、一次状态变化和转场。若有两位及以上主要角色，额外覆盖至少一个单人辨识镜头与一个群像镜头。单人到群像后身份仍须可辨；特写使用独立的细节素材，不直接放大低分辨率精灵。用户跳过样片时，以角色卡、动作条、关键帧和分镜检查继续，不渲染此阶段的视频文件。

将画法、角色/素材配置、分镜事件和字幕数据分开。提供由绝对成片秒或帧直接求值的画面入口，保存源曲偏移；粒子固定种子，状态由初态和该时点之前的事件推导。播放器播放、暂停、跳播与离线渲染共用这套求值逻辑。原生 Canvas 入口可命名 renderAtTime(t)；已有框架沿用其受支持契约。

事件须有可见后果，例如取得钥匙后道路开启，完成修理后出现可用载具和离开动作。动作、物件持握与遮挡保持连续。歌词在句起完整出现，持续到句止，长句换行而不裁字；任务提示及时退出并避开歌词。

提供本机实际可运行的预览命令。用户选择样片校验时，同时提供样片渲染命令；预览控件与成片绘制层分离，离线帧仅含演出内容，资源与字体加载就绪后才捕获。保存已请求的样片、分镜与检查记录。用户跳过样片时，保存代表静帧、分镜与检查记录。
```

完成判据：能在任意时点跳播；同一帧顺序、倒序求值结果一致；动作闭环成立；主要角色在动作条、近景与群像之间身份连续且可辨；歌词按实际音频核对。选择样片校验时，样片须来自真实渲染入口。静帧证明静态构图与角色设定；完整成片仍须按 E 阶段检查。

用户选择样片校验时，优先取能体现铺垫与爆发的副歌约 15 秒，连同对应音频评审；用户已指定范围则按其范围。依据进阶参考保存检查证据和未解决项，再进入 D。用户跳过样片时凭已通过用户确认的静帧、分镜和动作条进入 D。确认资料按静帧确认记录保存。

### D：扩展完整范围与局部修改

```text
复用通过检查的代表样片（如有）或已确认的风格表、静帧、角色动作与分镜，扩展到 BRIEF.md 中的完整范围。先检查歌词/镜头/事件覆盖目标时段，保持角色比例、画风、时间基准和资源 ID；重复副歌增加信息或后果。

分批完成并保存可继续工作的阶段成果。每批记录完成镜头、待补素材、未核对时点和渲染入口；每个未完成项都能定位到镜头或歌词 ID。中断后从这些记录恢复，不重新设计已经确认的段落。

若修改角色、字幕或一个镜头，先列出改动与受影响镜头，保留稳定 ID。先审受影响的静帧和动作条，提交改过的场景或人物请求重新确认，再渲染并检查相关转场。角色可辨度返工时只改失败角色及其受影响镜头，不把改色、加配件当成轮廓修复，也不顺手改已确认的音乐、故事和其他角色。美术修改沿用原时序；有意修改时间时重新检查该句、跨镜字幕和相邻事件。

保存当前可恢复版本，可用现有版本控制或工程内的版本副本。大改前保留最后一个可运行版本；更改失败时回退本轮改动，依据错误和受影响范围修正。输出完整范围预览和仍未解决的项，达到完整后才进入导出。
```

完成判据：首尾与全部目标时段被覆盖，没有占位素材或未说明的静止段；每次修改可确定影响范围并回退。若尚有歌词时间待核对，可交付草稿但应保留该状态。

### E：逐帧渲染、合音与验收

```text
按静帧确认与逐镜审片检查当前绘制入口和确认记录后，导出 BRIEF.md 指定范围。复用已确认角色、场景、字幕和时间数据。

以实际截取音频时长决定帧数，视频覆盖音频末尾且误差在已说明的逐帧范围内。原曲版本、速度、音高和内容按 brief 保留；只有用户要求时才加淡入淡出或改变音频。不得用缩短输出掩盖丢镜头、丢歌词或音频错位。

导出 MP4（常用 H.264/yuv420p 与 AAC，具体按目标渠道），成片包含所有演出图层，排除播放器按钮、文件选择、调试文字和光标。提供能复现的命令、锁文件、源文件、歌词/事件数据和本地资源来源清单。

用 FFprobe 核对实际音视频流、时长、尺寸、帧率与声道；用 FFmpeg 完整解码，抽查首尾、每镜、转场前后、动作落点及最亮/最暗字幕，再完整播放核对重要音画落点、动作连贯和文字阅读。只记录真正执行的检查与未解决项。
```

完成判据与命令见 依赖与交付。人工音乐同步检查和媒体技术检查分别记录；本轮仅编写教程或分镜时，不虚构成片验收结果。

### 统一时间与恢复记录

成片秒 `t` 与原曲秒 `sourceStart + t` 分开保存。数据不重复换算偏移；使用歌词 ID/镜头 ID 引用，避免修改一句歌词后重写所有场景。资源下载失败、字体缺字或框架渲染异常时，先保留成功的静帧、样片（如有）、数据和错误记录，再修正最小受影响部分。

```text
阶段：C 动态验证（可选）；当前版本：v03
目标：整曲（实测时长与源起止见 BRIEF.md）
已完成：角色 r1/r2、镜头 s01–s03、静帧与对应歌词校对；样片按需记录
待完成：s04–s12；l018 时间待核对
本轮修改：r1 持物锚点；影响 s02/s06；s02 复查通过
恢复入口：当前源文件、分镜数据、本地资源目录、实际启动/渲染命令
检查证据：静帧/样片（如有）路径、检查时点、已执行命令与未解决问题
```

利用本 skill 已有 `validate-storyboard.mjs`、`hud-density.mjs`、`film-sheet.py`、`safe-area.py` 与 `timeline-sync.py` 进行相应检查；它们各自的结果只证明所检查的属性。

# 审片与验收

[静帧与用户确认](#准备审批用的静帧) · [成片复核](#从最终视频复核并返修) · [定向优化](#进阶评审与定向优化) · [同步候选](#同步候选与可视化)

适用于新作、试片、整曲及改动角色或场景的返修。先在本项目实际绘制入口做关键静帧，执行自检并返修，再由用户分别确认场景和人物。批准的是图片所对应的版本与范围。用户要先看 60 秒时，只对这 60 秒排分镜和确认；续成整曲时沿用已认可的片段，另外确认新增或改动内容。

## 准备审批用的静帧

先在 BRIEF.md 记曲名、同版音轨、时间范围、背景和热评来源、原创立意、参考图、阶段状态与实际工具。分镜与视觉账本共用镜头 ID、歌词 ID 和成片秒。先做计划，再逐段实现静帧。逐项写可访问范围、要核的帧和仍待补的证据。

| 检查对象 | 使用项目画法出图 | 自检后写入对照表 |
|---|---|---|
| 每个场景和分镜 | 正式尺寸带字幕帧，按需要再出无文字版本。相同地点的回访并排。同镜内相似店铺单独截取。 | 场景 ID、镜头/歌词 ID、对应时段、初访或回访、可见行动和新信息。写出空间差异及核到的 PNG。 |
| 每位主角 | 独立全身远景和原生面部近景。对有表演的角色另做转面和本曲使用的眉眼、瞳孔、嘴形。 | 发型、脸型、服装剪裁和身形如何在远近景连续，两人剪影如何区分。 |
| 动作和姿态 | 对坐下、转身、互看、擦泪、递物、安装等，从准备到结果做连续帧。 | 支撑脚、臀部、膝至鞋底、肩肘腕、重心、手与物的接触、眼神、遮挡或裁边的理由。 |
| 片头和字幕 | 歌名首帧、第一项行动、第一句实际演唱各取一帧。抽实际最亮和最暗的字幕帧。 | 片名从首帧可读、装潢像故事的一部分，歌词进来的节奏和五官、手、道具及安全区。 |

### 查全片地点和细节

1. 按时间列出各镜实际地点，再按地点并排比较。优先给新事件设计有意义的新地点。连续行动可以在原地完成。回访要能从画面指出上次行动留下的变化、人物关系的新结果或另一项叙事信息。每次副歌复唱都加入这次的对照。
2. 去掉文字、招牌和手持标记，检查空间剪影与使用路径。花店可以从湿地面、花架和玻璃育苗棚认出，书店可以有深入室内的书架、阅读灯和用坏的门槛。相邻店面的开口、陈列、纵深、光向和人会怎样使用它们各自设计。推近、换色或换招牌都记为同一地点的变体。
3. 按正式尺寸逐场核主焦点、前中远景、轮廓负形、投影、反射或材质接触。物件至少有可辨形状、受光和使用状态。用原生像素截取核轮廓、脸、手和道具触点。全片同一像素语言，不同地点有自己的功能与光材质。和已认可成片对照完成度。
4. 视窗、门缝、电车窗和屏幕的内部对象裁进开口，再叠回该空间的边框与前景。若动作跨越开口，标清角色从哪一帧进入或离开遮挡层。衣物、支撑桌面和窗框的遮挡用整帧加近裁来核。

### 逐句核对观众能看到什么

在每句歌词下面填成片秒、歌词 ID、角色与物件、准备、关键动作、反馈、结果、后镜状态。先遮字幕问自己观众能看到什么，再看字幕文本和进入、离开时点。检查前后镜中道具的位置、持有者、角色视线和空间运动方向。可见内容依赖文字时，写明文字作为歌词、标题或有剧情原因的界面。

| 成片秒 / 歌词 ID / 镜头 ID | 观众此刻需要理解的事 | 可见顺序与时间 | 结果接给哪一镜 | 实际 PNG、问题、重查结果 |
|---|---|---|---|---|
| 示例 13.20–16.00 / L04 / S05 | 收到两人的照片后发现一格空着 | 13.20 出纸，14.00 伸手接，14.60 停看空格，15.40 另一人对视 | 次镜让空格影响贴相纸的位置 | 用本曲实际路径，逐项点出哪个画面证明动作发生 |

给有多个反应的镜头另写「观众看到」时间栏。依次标出视线被谁引到哪里、哪个动作在词头或重音处落下、结果清楚出现多久。保持一个主焦点，先找得着，后看得清。动作一闪而过时，用角色先看、局部亮度或镜头推近引导。接触后让结果多停几帧。歌词很密时，把动作接到下一句展开，音乐原速播放。下一句仍要增加信息，跨镜动作方向、物件状态和人物情绪连续。实唱时钟用相同录音与源偏移。抽象句用表情、地点或道具状态表达。片头与结尾可以用同一构图的一个变化，让观众读出决定发生在哪里。

### 分章制作时锁住共用资产

先完成一段代表性场景的静帧、姿态和构图，定下角色转面、配色、道具握点、字幕区和景深。每章单列地点、光色、人物情绪、歌词关键字和进出切点，沿用同一版共享角色与道具。分章并行时只改自己的镜头，统一由主工程整合共享素材。在章节接缝并排查看上一章最后一帧和下一章第一帧，核运动方向、大小、光色及道具归属。每个静态物件的粒子或纹理按自己的稳定 ID 与成片时间求值，检查一个物件移动时同层其他物件是否无故闪动。

参考做法来自《小镇姑娘》的章节调色、视觉意象接力及词头跨镜，以及原指南的观众阅读时序与元素随机种子。 [音乐视频流程](https://github.com/Joker-chichi/claude-mv-skill/blob/2ccf0c6ad31f27bb67e4a81e045e912f0a7d3e23/skills/painted-animation/references/music-video.md) · [动画指南](https://github.com/Joker-chichi/claude-mv-skill/blob/2ccf0c6ad31f27bb67e4a81e045e912f0a7d3e23/skills/painted-animation/template/ANIMATION_GUIDE.md) · [《小镇姑娘》分镜](https://github.com/Joker-chichi/claude-mv-skill/blob/2ccf0c6ad31f27bb67e4a81e045e912f0a7d3e23/skills/painted-animation/examples/xiaozhen/STORYBOARD.md)

## 把确认记录交给渲染器

请用户分别确认本次场景和人物，可以同一句答复。认可的人物和场景 ID、图片版本、回复依据和时间记入项目。只有选中范围全部确认才能做视频，包括动态样片和局部重渲。静帧与帧条可用于确认；样片按需求选择。确认后更换造型、地点、动作构图或字幕呈现时，交回受影响的静帧；保持原样的条目沿用已有回复。

确认文件例如 visual-review.json。下面的哈希栏用实际文件的 SHA-256 替换。Windows 可用 Get-FileHash -Algorithm SHA256，其他环境可用 shasum -a 256。记录里的相对路径以确认文件所在目录为准。场景与人物 ID 覆盖当前分镜 scenes 和 actors 的全部条目。每镜 frame 是实际输出尺寸 PNG，人物 wide 和 close 为内容各自独立的 PNG。可用 details 保存姿态和表情图。未获用户确认的 decision 留空。

```json
{
  "schemaVersion": 1,
  "storyboardSha256": "<当前分镜 SHA-256>",
  "reviewedAt": "<用户确认时刻，含时区 ISO 时间>",
  "renderSettings": { "font": "Microsoft YaHei" },
  "sources": [{ "path": "frame.mjs", "sha256": "<绘制文件 SHA-256>" }],
  "scenes": [{
    "id": "scene-01",
    "frame": { "path": "stills/scene-01.png", "sha256": "<确认图 SHA-256>" },
    "decision": "<用户确认场景的回复依据>"
  }],
  "actors": [{
    "id": "lead",
    "wide": { "path": "stills/lead-wide.png", "sha256": "<确认图 SHA-256>" },
    "close": { "path": "stills/lead-close.png", "sha256": "<确认图 SHA-256>" },
    "decision": "<用户确认人物的回复依据>"
  }]
}
```

sources 登记实际绘制源文件、导入的场景代码、自定义字体和会改变外观的素材。starter 至少包含 frame.mjs、frame-core.mjs、timeline.mjs、png.mjs、export.mjs。字体记录与导出时选用的 --font 或平台默认一致。用户确认前可用 --frame-final 单独查看同一 ASS 字幕。更改分镜、确认图、已登记绘制文件或字体会使旧记录失效。

使用 Python 内置最小渲染器时传 --review，并列出 minimal-renderer.py 和该项目使用的绘制素材；自定义 Python、HyperFrames、Remotion 等入口在首个写帧或编码命令前调用 [review-gate.mjs](../assets/templates/starter/review-gate.mjs)，传实际主入口及参与绘制的文件。它检查覆盖和版本。用户原话、取图过程与画质由制作方核验并记在项目。含占位音轨但实质是本曲成片美术的项目，同样执行静帧确认，可在 JSON 加 project.visualReviewRequired: true。

```sh
node /path/to/starter/export.mjs --storyboard storyboard.json --frame-time 2.5 --frame-out work/scene-01.png --frame-final
node /path/to/starter/export.mjs --storyboard storyboard.json --review visual-review.json --out output.mp4
node /path/to/starter/review-gate.mjs --storyboard storyboard.json --review visual-review.json --source render.py --source art.py
```

演示分镜和技术检查卡可直接导出。真实歌曲的可试听片段、帧序列和成片使用同一确认记录，纯技术检测仍按实际工具执行。

## 从最终视频复核并返修

1. 用 FFprobe 实查分辨率、帧率、时长、音视频流和声道。用 FFmpeg 完整解码。场景起中末、预定事件和出入转场有索引，抽取实际 MP4 的正式尺寸 PNG。看前后帧序列判断视线、肢体、接物、字幕和过渡，关键点补逐帧条及原尺寸脸、手或道具裁图。
2. 从头播放或看片到结束，核全片歌词、动作与空间。每处跨镜和副歌复唱都检查。自然的留白可保留，记下画面上承接的动作或状态。抽帧、时长和自动指标可定位问题，实际动画变化和输出 FPS 分别验证。对问题片段查相邻帧步进及重复帧，区分有意停顿和画面跳动。
3. 看最后混入的提示音事件、相对音乐电平、真峰值和听感。无法人工复听时，把待听区间和原因留在交付说明，音乐证据维持 draft。连续台词、歌词句界和卡点以实际录音为准。
4. 项目审片表逐镜写已查看的帧、具体问题、修复路径和新证据。换景、坐姿、遮挡、前奏、歌词与节奏触点失败时修后复查相邻镜头。确认记录覆盖的视觉修改回到上面的静帧确认，再重渲。提供最终文件、可修改工程和检查记录。

```sh
node /path/to/qa.mjs --review-index storyboard.json --out work/shot-index.json
python /path/to/film-sheet.py output.mp4 --review-index work/shot-index.json --review-dir work/review-final
python /path/to/film-sheet.py output.mp4 --review-index work/shot-index.json --review-dir work/review-touch --strip 14.5 15.0 --crop 760 420 500 400
```

关键转身、递物、落座或转场用 --strip 查看该段每一帧。人脸、手、支撑脚用 --crop 按原始像素宽高裁切。运镜时，固定裁框可能切掉动作。先选不同区间的画面坐标，或由项目的摄像机把同一个世界锚点投影到每帧，再沿该点裁图。先开图实际看，再记录通过与返修。

starter 的 MP4 旁车会校验分镜与视频哈希。使用其他渲染器时应提供同版导出记录；没有旁车的索引只比较帧率和帧数，审片前仍需确认视频来自这版分镜。

交付表可用「镜头 ID｜取样帧｜构图和人体｜无字情节和道具｜歌词和切点｜结果与复查路径」。需要人工判断的一栏，看到真实画面才填写通过。

### 连续动作、物件细节与节奏复看

把前奏、第一轮副歌和重复副歌各看一段连续视频。先遮字幕，指出观众能读出的预备、接触和结果；再关闭新增提示音，判断还能听出哪些音乐强调。检查人物承重和手与道具的接触，关键近景单独画眼睑、手指、握点与材质受光。让唱片的刻纹随盘旋转、金属刻度保持固定、衣袖随手臂产生褶皱。用实际尺寸及手机大小分别看一遍，避免布景虽多，播放时只看到静帧平移、反复按键或无缘由的放大。镜头表记录修改前后的具体时段与可见差异。

## 进阶评审与定向优化

适用：已有歌词驱动或像素 MV 像 PPT、高潮弱、构图重复、角色怪、画面糊、转场僵硬，以及从代表片段扩展到整片时的质量控制。动态样片可按任务需要选择；保留已确认音乐、故事、框架和授权范围，从现有工程继续。

教程展示 `Opus 5.5`、`DeepSeek`、`gpt-image-2.6` 和 `HyperFrames` 名称，只证明画面有这些名称。实际可用模型、API、费用及框架契约以当前环境为准。四种景别、1.5–4 秒镜长、每文件 300 行、所有镜头写成一个网页等是示例建议，按作品和工程选择。视觉评分也不能预测播放量。

### 先评审，再修改

先记录成片版本、目标区间、源曲偏移、已确认内容和可用证据。优先修最影响观看的几处，然后逐镜累计其余问题。每项写时间、镜头 ID、表现、依据、修改处和复核办法。适用整片制作时按静帧确认与逐镜审片覆盖全部画面，新改的造型和场景请用户重新确认后再进行动态返修。

#### 五个评分维度

教程采用 10 分制，权重为美术 35%、表现力 25%、动画 15%、歌词和故事 15%、细节 10%。可作为默认量尺；用户已有量尺则沿用，在复评前固定权重与观察范围。

| 维度 | 权重 | 低分症状 | 高分依据 | 所需证据 |
|---|---:|---|---|---|
| 美术 | 35% | 角色身份漂移、像素尺度混杂、构图难辨 | 身份统一、层次清楚、关键构图有辨识度 | 设定图、全片接触表、原尺寸与输出帧 |
| 表现力 | 25% | 主副歌视觉强度相同、重音无回应 | 铺垫与爆发有区别，关键音乐变化有叙事动作回应 | 实际音频与对应动态片段、时间表 |
| 动画 | 15% | 脚滑、肢体突跳、道具漂浮、转场断裂 | 准备→峰值→结果连贯，运动/接触与转场成立 | 动作条、动态片段、边界逐帧检查 |
| 歌词和故事 | 15% | 只有字幕、重复副歌原样重播、事件无结果 | 画面承担歌词含义，重复段落有发展 | 校对歌词、分镜/事件、对应画面；同步另需音频 |
| 细节 | 10% | 字幕截字、放大重影、HUD 遮挡、素材占位 | 亮暗字幕可读，最大推近清晰，边界与安全区正确 | 最大推近/亮暗/首尾/转场帧、输出参数 |

建议锚点：0–2 为核心内容缺失或严重失效；3–5 为明显问题影响观看；6–7 为可读可用但仍有可定位缺陷；8–9 为目标范围内稳定且有表现；10 为该范围证据充分、未见相关缺陷。每项附具体证据，分数是评审判断，不是客观质量测量。教程的“7 分以上精致耐看”不作为通用交付门槛。

五项都可评时，总分 `0.35×美术 + 0.25×表现力 + 0.15×动画 + 0.15×歌词故事 + 0.10×细节`，保持 0–10 分尺度。部分证据缺失时输出可评维度和“未评/待核对”，不以零分填缺项，也不计算完整总分。只评样片时明确样片范围；全片评分需要检查全片，不能从样片推广。

```text
版本/范围：v03；成片 s05 与相邻转场；源曲偏移见 BRIEF.md
可用证据：接触表、动态样片、原曲；核对范围：……
维度｜修改前分数｜证据时间/帧/镜头 ID｜缺陷或限制
问题 ID｜现象与原因｜修改文件/字段｜预期可见变化｜复核证据
复评：同范围、同量尺；新版本与前版对照；改善/未改善/新问题
```

### 五类问题的定向修正

| 问题 | 改哪里 | 复核结果 |
|---|---|---|
| 没有高潮 | 标注副歌及少量关键重音；选择动作幅度、机位、光色或空间尺度的强弱变化 | 铺垫与爆发可辨，动作峰值落到已试听核对的点，歌词仍可读 |
| 画面单一、镜头不动 | 依据人物任务改变景别/方向/构图；重复段落改变事件结果 | 接触表展示发展；长镜内部有有效演出，镜头运动有目的 |
| 人物奇怪 | 修动作表、接触和持物锚点；必要时简化造型或采用素材路线 | 同一角色身份稳定，脚/手/道具连续，原尺寸与输出都成立 |
| 画面模糊 | 查素材、画布/CSS尺寸、插值、缓存及重复缩放 | 最大推近边缘和文字清晰；像素块规则，普通栅格细节足够 |
| 越做越差、转场僵硬 | 回到最后可运行版本，修副歌或受影响片段；统一转场时钟 | 修改前后同点比较无回退，边界连贯，再按授权范围扩展 |

节奏由歌曲与叙事决定。每 2 秒抽帧是检查频率；并非每 2 秒切镜。等待、余韵和母题回扣可以保留固定构图，判据是是否承担当前段落信息。副歌不必最亮、最快，悲伤或克制的歌可用更强空间/动作含义表现高潮。选少量有意义重音响应，保持阅读时间，避免频闪式整屏闪白。

### 角色与清晰度

先保留角色 ID、轮廓、发型/装束、身形比例、尺寸、朝向、脚底锚点、持物锚点和图层遮挡。若反馈是“像同一个模板换色”，先做等尺度纯黑剪影对照：隐藏名字、配色和小道具，检查头部轮廓、服装外轮廓、身形/重心、姿态中至少两类能否区分每个主角；不能区分时先重画对应角色卡，不用加色、加饰品或滤镜掩盖。再在群像的最小实际输出尺寸复核，单人近景使用独立资产，不直接放大小精灵。动作按需要设计站立、走、跑、跳或挥手；循环动作检查末帧→首帧，拾取/拥抱等一次性动作检查准备→接触→结果，不强行循环。详细门槛见 像素世界与演出。

素材生成是可选路线。优先复用已有动作条；没有生成服务时用本地绘制、像素小人、纸偶或简化五官完成授权动作。需要外部生图时先说明服务、Key、费用和下载/安装需求，并沿用已有授权。生成图只是候选素材，须检查身份一致、切片边缘、透明底、脚底稳定、肢体和道具后接入。

动作表建议每个动作单独一张，等尺寸格子、固定朝向和机位，记录格宽/高、帧数、帧率、锚点及是否循环。教程的“6 帧、3×2、12 fps”可作候选，实际依动作长度选择。单独画接触动作草稿核对双人站位和手部关系。透明底优先；若抠色底，确认底色未出现在人物中并检查边缘污染。PNG 换成 SVG 包装不会增加细节；只有实际矢量路径或足够分辨率绘制能支持对应放大。

**最大显示尺寸预算：** 普通栅格图/缓存至少覆盖其最大屏幕显示尺寸，包含对象占屏尺寸与最大镜头倍率；矢量在目标输出尺寸重绘。背景要覆盖最大显示及运镜露出的区域。别把导出分辨率当成素材已经够清晰的证明。

例如内部画布 `480×270`、输出 `1920×1080`，输出比例为 4；角色内部显示 `48×64`，最大推近 `1.5`，则峰值屏幕尺寸为 `48×4×1.5 = 288`、`64×4×1.5 = 384`。普通栅格角色要有对应细节预算；**有意设计成 48×64 的像素角色可保留原像素，以 6 倍最近邻显示，无需重采样成 288×384 来伪装高清。** 特写需更多细节时制作对应像素尺度的特写素材。中间推近倍率、摄像机坐标和世界层边界要检查像素不均/闪动；中文字幕保持独立清晰层。

Canvas 每次设宽高或重置后重新设置 `imageSmoothingEnabled=false`；CSS 像素显示使用 `image-rendering:pixelated`。在最强推近、动作峰值和实际输出的 100% 尺寸检查，不只看缩略预览。统一摄像机变换、时钟和渲染尺度可跨多个绘制层实现，并不要求改成单个 Canvas。

### 样片与转场

已有范围从当前阶段继续。画面升级优先截取副歌约 15 秒及必要的铺垫/转场，配对应原曲；用户限定局部时只改授权位置及其影响。用户选择动态验证时，完成样片后用同表复评，通过当前目标检查才扩展。用户跳过动态样片或交付范围是 skill/方案/分镜时，用关键帧接触表、静帧、事件数据和时间/转场检查完成当前阶段。最终成片或动态问题仍依据实际目标画面复核。每批保存版本、受影响镜头和未解决项；出现回退时恢复本轮前版并定位原因，当前范围完成即停止，分数不扩大改动范围。

沿用现有 HTML、HyperFrames 或 Remotion 工程，把相邻镜头的转场状态纳入同一绝对成片时钟：边界附近按效果需要让两个世界状态同时可绘制，以前景遮挡、物体/形状匹配、连续机位或明确有意的硬切衔接。镜头文件可以分开，播放与离线渲染使用同样的时间求值入口。教程的“一个网页”指向连续编排思路，不要求迁移现有框架或合并所有源文件。

选取核对过的音乐点 `b`；需要准备动作时，以 `b-lead` 起步、在 `b` 到达接触/构图目标，`lead` 可先试 0.2–0.5 秒再依音乐调整。让运动有准备、峰值与收束，字幕/HUD保持独立阅读位置。选择动态验证时，在转场前后补帧并动态播放，检查任意 seek 和倒序求值后的同帧一致性；跳过动态验证时，把这些项目列为待验证。刻意的硬切、静止和叠化可以服务叙事，不按效果种类一律判失败。

## 同步候选与可视化

当需要一起查看音频能量、局部拍点、镜头切点与字幕落点时，使用 `scripts/visualize-sync.mjs`。它只用 Node 内置模块，输出可用浏览器打开的 SVG 和同名 JSON。它不渲染视频、不识别歌词、不替代试听，也不会改写分镜或改变 `music.status`。

### 生成与查看

先让 `analyze-audio.mjs` 对实际使用的成片音频区间生成标准报告，再生成图：

```sh
node scripts/analyze-audio.mjs path/to/song.mp3 --start 37.2 --duration 12 --out work/analysis.json
node scripts/visualize-sync.mjs storyboard.json work/analysis.json --out work/sync-review.svg
```

这些命令以技能目录为当前目录；实际工程中可使用脚本的绝对路径。第二条同时生成 `work/sync-review.json`。输入报告必须是 `schemaVersion: 1`、`status: "draft"`、`timebase: "clip"` 的 `analyze-audio.mjs` 报告；不直接兼容其他分析器的私有字段。

图的轨道共用成片秒时间轴：归一化 RMS 能量、多频带瞬态候选、可观测/预测拍点、镜头区间和字幕区间。悬停区间可以查看 ID、时间与候选误差。JSON 保留局部拍点置信值、观测/预测来源、全部区间、误差、摘要和两份输入的 SHA-256，便于确定复核针对哪版分镜和分析结果。JSON 中的 `status: "candidate-review"` 表示检查图的性质，不是音乐校对等级。

`project.sourceOffset` 与分析报告的 `sourceOffset` 必须一致。例中均为 37.2；图上仍从 0 秒开始，不再额外加 37.2。若分析的是已经裁好的音频，分析器会记录 `sourceOffset: 0`，而分镜仍保存原曲偏移，则优先从原曲按同一 `--start` 重新分析。只有确实知道裁切来源时，才在分析报告副本中补回来源偏移，并另行记录原曲到裁切文件的关系；不要把错配当成普通偏差。

时长比较允许一个 PCM 样本或 `1e-6` 秒的舍入差；原曲偏移比较允许 `1e-6` 秒。区间端点允许 `1e-6` 秒舍入，实际越界、空区间和不连续镜头仍会拒绝。节拍严格属于 `[0, duration)`，不能把成片终点写成可渲染拍点。

### 如何解释误差

报告将每个内部镜头切点和明确标记 `sync:"beat"` 的场景事件列入 `alignmentSuggestions`，并另行比较歌词字幕起点：

```text
deltaSeconds = 起点 - 最近候选拍点
```

正数表示较晚，负数表示较早；两个拍点距离相同时取较早拍点。`alignmentSuggestions[].suggestedAt` 只为置信值达到 0.65 的候选提供吸附建议，`status` 会区分可复核、已在容差内、低置信、缺少证据及无候选。默认容差 80 ms，可从 `project.settings.beatToleranceMs` 读取。该报告只列建议，不自动改时间；人工确认后才把 `suggestedAt` 写回分镜。`summary.internalSceneStarts` 排除片头 0 秒，统计内部镜头起点的平均和最大绝对候选误差；`summary.captionStarts` 统计字幕起点。没有候选拍点时图仍可生成，最近拍点与误差为 `null`。

这些数值用于发现可能的错位，不构成“落点正确”的分数。BPM 网格可能半速、双速、漂移或因乐器瞬态而不对应主节拍；长音拖尾、弱拍、语义转折、转场预卷和留白也可能需要偏离候选点。先核听实际音轨，确认节奏与局部落点，再决定动作是否跟拍。不要为了压低平均误差，把所有字幕或镜头都吸附到拍点。

### 器乐与叙事字幕

器乐曲可以配原创词作或叙事字幕。说明它们是屏幕叙事文案，不是音频中的演唱转录。可在分镜说明中记录字幕角色；本工具若读到可选 `music.captionRole` 或顶层 `captionRole` 文本，会原样标在图上，否则显示 `unspecified`。角色字段只是图示元数据，不代替授权记录或人工复核依据。

器乐落点可结合段落变化、能量、节奏与文意选择。`verified` 取决于已完成的人工检查和证据记录；不能仅因没有人声就固定为 `draft`，也不能凭生成这张图升级为 `verified`。

### 规模与边界

- 每份输入最多 16 MB，成片区间最多 600 秒；源音频不会被这个脚本读取或校验。
- 最多 500 个镜头、1000 条字幕、12000 个候选拍点、150000 个包络点。超限时缩短区间，不静默丢弃区间或节拍。
- 包络超过 1600 点时按桶保留最小/最大值，保留短促能量峰；JSON 记录原始与显示点数。图不是原始波形。
- 字幕轨道循环使用 7 条显示行，重叠或密集字幕可能在图上遮挡；精确区间以 JSON 为准。`textPreview` 最多 300 字符，完整文案仍在输入分镜。
- SVG 与 JSON 分别限制 4 MB。输出不能覆盖任何输入；重新生成自己的报告可使用同一输出名。
- 两个新报告先写入同目录临时文件，备份旧输出后成对提交；可处理的提交错误会恢复原来的两个文件。输出为目录时在替换前拒绝。若回滚也失败，报错会给出保留备份的目录，先恢复旧文件或检查备份，不要直接删除该目录。
- 图中的 SHA-256 绑定分镜和分析报告，不证明分析使用了正确音轨。音轨内容、裁切和许可记录仍需在工程交付流程中核对。


### 角色剪影盲测
如制作动态样片，两位及以上主角须在进入样片前提交等尺度纯黑剪影表；隐藏姓名、颜色和小道具后，仍需凭轮廓、比例或姿态区分每人。跳过样片时，可直接用剪影表、关键帧和尺寸对照检查静态辨识度。

# 音频、镜头与字幕的同步候选检查

当需要一起查看音频能量、候选拍点、镜头切点与字幕落点时，使用 `scripts/visualize-sync.mjs`。它只用 Node 内置模块，输出可用浏览器打开的 SVG 和同名 JSON。它不渲染视频、不识别歌词、不替代试听，也不会改变分镜的 `music.status`。

## 生成与查看

先让 `analyze-audio.mjs` 对实际使用的成片音频区间生成标准报告，再生成图：

```sh
node scripts/analyze-audio.mjs path/to/song.mp3 --start 37.2 --duration 12 --out work/analysis.json
node scripts/visualize-sync.mjs storyboard.json work/analysis.json --out work/sync-review.svg
```

这些命令以技能目录为当前目录；实际工程中可使用脚本的绝对路径。第二条同时生成 `work/sync-review.json`。输入报告必须是 `schemaVersion: 1`、`status: "draft"`、`timebase: "clip"` 的 `analyze-audio.mjs` 报告；不直接兼容其他分析器的私有字段。

图的四条轨道共用成片秒时间轴：归一化 RMS 能量、机器候选节拍、镜头区间、字幕区间。悬停区间可以查看 ID、时间与候选误差。JSON 保留全部区间、候选拍点、误差、摘要和两份输入的 SHA-256，便于确定复核针对哪版分镜和分析结果。JSON 中的 `status: "candidate-review"` 表示检查图的性质，不是音乐校对等级。

`project.sourceOffset` 与分析报告的 `sourceOffset` 必须一致。例中均为 37.2；图上仍从 0 秒开始，不再额外加 37.2。若分析的是已经裁好的音频，分析器会记录 `sourceOffset: 0`，而分镜仍保存原曲偏移，则优先从原曲按同一 `--start` 重新分析。只有确实知道裁切来源时，才在分析报告副本中补回来源偏移，并另行记录原曲到裁切文件的关系；不要把错配当成普通偏差。

时长比较允许一个 PCM 样本或 `1e-6` 秒的舍入差；原曲偏移比较允许 `1e-6` 秒。区间端点允许 `1e-6` 秒舍入，实际越界、空区间和不连续镜头仍会拒绝。节拍严格属于 `[0, duration)`，不能把成片终点写成可渲染拍点。

## 如何解释误差

每个镜头起点、每条字幕起点都与最近的机器候选拍点比较：

```text
deltaSeconds = 起点 - 最近候选拍点
```

正数表示较晚，负数表示较早；两个拍点距离相同时取较早拍点。`summary.internalSceneStarts` 排除片头 0 秒，统计内部镜头起点的平均和最大绝对候选误差；`summary.captionStarts` 统计字幕起点。没有候选拍点时图仍可生成，最近拍点与误差为 `null`。

这些数值用于发现可能的错位，不构成“落点正确”的分数。候选网格本身可能半速、双速或漂移；拖音、弱拍、语义转折、转场预卷和留白也可能需要偏离候选拍点。先试听实际音轨，核对候选，再决定哪些画面动作需要跟拍。不要为了压低平均误差，把所有字幕都吸附到拍点。

## 器乐与叙事字幕

器乐曲可以配原创词作或叙事字幕。说明它们是屏幕叙事文案，不是音频中的演唱转录。可在分镜说明中记录字幕角色；本工具若读到可选 `music.captionRole` 或顶层 `captionRole` 文本，会原样标在图上，否则显示 `unspecified`。角色字段只是图示元数据，不代替授权记录或人工复核依据。

器乐落点可结合段落变化、能量、节奏与文意选择。`verified` 取决于已完成的人工检查和证据记录；不能仅因没有人声就固定为 `draft`，也不能凭生成这张图升级为 `verified`。

## 规模与边界

- 每份输入最多 16 MB，成片区间最多 600 秒；源音频不会被这个脚本读取或校验。
- 最多 500 个镜头、1000 条字幕、12000 个候选拍点、150000 个包络点。超限时缩短区间，不静默丢弃区间或节拍。
- 包络超过 1600 点时按桶保留最小/最大值，保留短促能量峰；JSON 记录原始与显示点数。图不是原始波形。
- 字幕轨道循环使用 7 条显示行，重叠或密集字幕可能在图上遮挡；精确区间以 JSON 为准。`textPreview` 最多 300 字符，完整文案仍在输入分镜。
- SVG 与 JSON 分别限制 4 MB。输出不能覆盖任何输入；重新生成自己的报告可使用同一输出名。
- 两个新报告先写入同目录临时文件，备份旧输出后成对提交；可处理的提交错误会恢复原来的两个文件。输出为目录时在替换前拒绝。若回滚也失败，报错会给出保留备份的目录，先恢复旧文件或检查备份，不要直接删除该目录。
- 图中的 SHA-256 绑定分镜和分析报告，不证明分析使用了正确音轨。音轨内容、裁切和许可记录仍需在工程交付流程中核对。


## 角色剪影盲测
三人以上主角在进入样片前，提交等尺度纯黑剪影表；隐藏姓名、颜色和小道具后，仍需凭轮廓、比例或姿态区分每人。

# 音效层与卡点

给代码生成的 MV 加音效，难点不在"发声"，而在**两层对齐关系**。弄反了，音效会和音乐打架。

## 结论先说：两层结构

```
画面变化（切镜、数字跳变、大字、元素出现）
        └─ 落在音乐拍点上     ← music.beats，容差 80ms，由校验器判
音效（tick / type / whoosh / confirm …）
        └─ 与画面变化同帧     ← offset 应接近 0，不跟拍点
```

**音效不该踩拍。** 它踩的是画面。画面已经在拍点上了，音效再踩一次等于同一拍被强调两遍，听感会发木。

## 参考片实测（2 条片子，读出来的数）

对一条 209 秒的数据可视化叙事片（FlovaAI 风格，深紫底、折线图与仪表盘）做宽带瞬变检测：10 ms 帧、5 ms 步进，取 4–7.8 kHz 能量占比相对 200 ms 基线的突增，并叠加总能量起音条件。

```
时长 209.10s | 宽带瞬变候选 218 个（每分钟 62.6 个）
与 132.3 BPM 网格（相位 0.4435s）比对：|offset|<80ms 84/218，中位 |offset| 141.1ms
间隔：中位 0.42s，25% 0.22s，75% 0.68s
前 8 个候选：0.01 / 0.46 / 0.92 / 1.37 / 1.82 / 2.28 / 4.79 / 5.46（秒）
```

两个数一起看才有意义：

- **密度**：每分钟 62.6 个 ≈ 每秒 1 个。这类片子几乎每个可见变化都带一声，但都很短（几十毫秒）。
- **相位**：只有 38% 落在 80 ms 内，中位偏离 141 ms。**如果作者想让音效踩拍，不会是这个分布。**

也就是说，参考片的"卡点感"来自：画面整齐地落在拍上，音效密密麻麻地跟着画面。音效本身是"贴图"，不是"鼓点"。

同一条片子的画面侧特征（24 帧接触表读出）：全片一套深紫仪器面板语言，大字数字（1897 / 120 / 15 年 / 89% / 63% / 98）逐个出现，每个数字出现都伴随一次高频轻响；章节牌切换处是扫风。

另一条 63 秒扁平插画片（"什么是世面"）换了语言但结构相同：顶部一行大字随场景整句替换，场景切换干净利落，音效贴在切换点上。

## 八种音效，各有用途

| type | 时长 | 音色 | 用在哪 |
|---|---|---|---|
| `tick` | 45 ms | 1200 Hz 方波，极短 | 数字跳变、刻度经过、进度推进 |
| `type` | 100 ms | 三连短噪 | 一行字被"打"出来（打字机） |
| `click` | 35 ms | 2200 Hz + 噪声 | UI 按钮、光标确认 |
| `whoosh` | 420 ms | 噪声中频扫到高频 | 转场、章节切换 |
| `confirm` | 220 ms | 880→1320 Hz 上行 | 勾选、达成、条件满足 |
| `error` | 300 ms | 520 Hz 下行锯齿 | 失败、归零、条件不满足 |
| `riser` | 600 ms | 180 Hz 起六倍频上行 | 段落进入前的预热 |
| `chime` | 850 ms | 523/659/784 Hz 三音和弦 | 结算、收束、结尾 |

全部由代码合成（确定性噪声 + 振荡器 + 包络），不含任何采样素材，因此没有授权问题，也不需要下载。

## 怎么写进分镜

音效写在与画面同一层，而不是另开一条时间轴——这样它和画面事件会被同一份校验器检查：

```json
{
  "project": {
    "duration": 12,
    "sfx": [{ "at": 0, "type": "riser", "gain": 0.40 }]
  },
  "scenes": [
    {
      "id": "send",
      "start": 0,
      "end": 6,
      "events": [
        { "at": 1.5, "action": "灯亮的一瞬落在拍上", "sync": "beat" },
        { "at": 3.0, "action": "数字跳到 42", "sync": "beat" }
      ],
      "sfx": [
        { "at": 1.5, "type": "tick", "gain": 0.60 },
        { "at": 3.0, "type": "tick", "gain": 0.50 }
      ]
    }
  ]
}
```

字段：

- `at` 成片秒，必须 `>= 0` 且 `< project.duration`。
- `type` 见上表，写错类型校验器直接报错并指出 `project.sfx[0].type` 或 `scenes[1].sfx[0].type`。
- `gain` 0–2，默认 1；`pitch` 0.5–2，默认 1（同时改时长）。
- 转场音可以放在后一镜的 `sfx[]` 里，`at` 写成两镜交界处。

完整示范见 [storyboard-sfx-demo.json](../assets/storyboard-sfx-demo.json)：事件全部落在 0.5 s 拍点网格上并标 `sync:"beat"`，每个事件配一个同帧音效。

## 渲染与混音

推荐一条命令，导出时直接把音效混进去：

```powershell
node export.mjs --storyboard storyboard.json --audio 你的歌.wav --sfx --out work/final.mp4
node export.mjs --storyboard storyboard.json --audio 你的歌.wav --sfx --sfx-gain 0.7 --out work/final.mp4
```

`--sfx` 内部做三件事：读 `project.sfx[]` 与 `scene.sfx[]` → 合成 `sfx.wav` → `amix` 混进 `audio.wav` 再编码。混音结果覆盖内部 `audio.wav`，所以 `.mp4.assets.json` 里记录的哈希是最终音轨。分镜里没有任何 sfx 时直接报错，不会悄悄导出一条没有音效的片子。

要单独拿音效轨（贴进别的剪辑软件），或自己控制权重与限幅：

```powershell
# 1) 合成一条独立音效轨（长度严格等于 project.duration）
node scripts/sfx.mjs --from-storyboard storyboard.json --out work/sfx.wav --report work/sfx-report.json

# 2) 导出（不带音效的）成片
node assets/templates/starter/export.mjs --storyboard storyboard.json --out work/demo.mp4

# 3) 混音：音乐 1.0，音效 0.85
ffmpeg -y -i work/demo.mp4 -i work/sfx.wav -filter_complex "[0:a][1:a]amix=inputs=2:duration=first:weights=1 0.85:normalize=0,alimiter=limit=0.95" -c:v copy -c:a aac -b:a 192k work/final.mp4
```

实测（12 秒示范片，9 个音效事件，一条命令版）：

```
音效 9 个（每分钟 45 个）已混入音轨，权重 0.85；1 个越界事件被裁在片尾
成片：h264 + aac，48 kHz 立体声，duration 12.000000
```

「1 个越界事件」是正常的：11.5 s 的 `chime`（850 ms）会越过 12 s 边界，被裁在片尾。渲染器在首尾各做 8 ms 淡入淡出，所以截断处不会爆音。

## 怎么验证音效真的在（别只靠听）

对比"只有音乐"和"音乐+音效"两条轨，在事件时刻取窗口，看差值是否起于该时刻（一条命令导出的两个版本）：

```
采样率 16000 | 事件 9 个 | 全片基线差值 RMS 0.00961
    事件 类型      窗口差值RMS    峰值差  相对基线  局部对比  判定
    0.00 riser       0.0006   0.0022    0.1x    71.00x  命中
    1.50 tick        0.0266   0.1638    2.8x  1789.00x  命中
    3.00 tick        0.0226   0.1357    2.4x  1481.67x  命中
    5.00 type        0.0159   0.0995    1.7x   651.80x  命中
    6.00 whoosh      0.0100   0.0208    1.0x   227.67x  命中
    9.00 confirm     0.0242   0.1174    2.5x  1282.67x  命中
    11.50 chime      0.0604   0.1818    6.3x  1985.33x  命中
命中 9/9

起音位置检查（±窗口外 60–160ms 的差值应明显小于事件窗口）：
    0.00 riser     前 0.0000 | 内 0.0004 | 后 0.0043
    1.50 tick      前 0.0000 | 内 0.0240 | 后 0.0001
    5.00 type      前 0.0000 | 内 0.0127 | 后 0.0002
    6.00 whoosh    前 0.0000 | 内 0.0070 | 后 0.0424
```

「前 0.0000 / 内 0.0240 / 后 0.0001」这三段的关系是判据：事件前完全静音，事件内有明显能量，事件后立刻衰减。若三段差不多大，说明音效没在某一点起音，而是铺满了整段。`6.00 whoosh` 的"后 0.0424"是因为扫风本身有 420 ms 尾巴，属正常。

注意对比基线要在**同一条编码路径**上取：分步混音（先导 MP4 再混）会因为 AAC 二次编码产生 0.0495 的基线差，一条命令版只有 0.0096。基线越干净，判据越灵敏。

## 边界

- 音效合成不证明"好听"。它只保证落在你要的时刻、长度严格等于成片、不削顶。
- 混音权重按片子调：数据可视化片（密集 tick）建议 0.7–0.85；叙事片（少而重）建议 0.9–1.0。
- 音效不能替代音乐证据状态。`music.status` 仍按 [时间与分镜](storyboard-and-timing.md) 的规则填 `illustrative` / `draft` / `verified`。
- 全部音效都是合成音，不带人声与环境声。需要真实环境音时另找素材并记录授权。
